# VoxelCraft

TypeScript と three.js で作った、ブラウザで動くボクセルサンドボックスゲーム。
自動生成される地形を掘り、素材を集め、道具を作り、夜に湧く敵をしのぎ、畑を耕し、村人と取引する。
村にはそれぞれ生産品があり、村と村を歩ける道でつなぐと荷運びが商品を運びはじめ、村が発展する。
水はボクセル単位で量を持つ流体シミュレーションで、川をせき止め、水路を引き、水門で流れを操れる。

外部の画像アセットは一切使わない。ブロックとアイテムのテクスチャは起動時に Canvas 2D で
手続き的に描かれ、1 枚のアトラスに合成される。

```bash
npm install
npm run dev      # http://localhost:5173 を開く
```

## 遊び方

| 操作 | 動作 |
| --- | --- |
| `W` `A` `S` `D` | 移動 |
| `Space` | ジャンプ（水中では浮上。岸に向かって泳げばそのまま陸に上がれる） |
| `Ctrl` | ダッシュ |
| `Shift` | 忍び足（設置対象のブロックを開かずに置く） |
| マウス移動 | 視点（最初に画面をクリックしてカーソルを固定） |
| 左クリック | 採掘（長押し）/ 攻撃 |
| 右クリック | 設置・使用・食べる・作業台/かまど/チェストを開く・村人と取引・**シャベルで道を敷く** |
| `1`〜`9` / ホイール | ホットバー選択 |
| `E` | 持ち物（レシピ一覧・防具） |
| `F3` | デバッグ表示（座標・バイオーム・シードなど） |
| `Esc` | 画面を閉じる / ポーズ（描画距離・マウス感度・便利機能の切り替え） |

クラフトは**マスに材料を並べる方式ではない**。レシピ一覧から作りたい物をクリックすると、
持ち物のどこにある材料でも自動で消費される。Shift+クリックで作れるだけまとめて作る。
材料が足りないレシピも不足分を表示したまま並ぶので、一覧がそのままレシピブックになる。

### 最初の 10 分

1. 木を殴って**原木**を取る → `E` を開いて木材・棒・**作業台**をクリックで作る
2. 作業台を置いて開くと道具と防具のレシピが解禁される。木のツルハシ → 石を掘って**石の道具**
3. **石炭**と**松明**を作り、暗い場所を照らす（明るい場所には敵が湧かない）
4. 日が暮れる前に囲いを作るか洞窟に隠れる。ゾンビ・スケルトン・クモが湧く
5. 動物を狩って肉を焼き、**満腹度**を保つ。空腹だと体力が減る
6. **鉄鉱石**を石のツルハシで掘り、かまどで精錬して鉄の道具・防具へ
7. **村**を探す。チェストに物資があり、村人とエメラルドで取引できる
8. クワで土を耕し、種を植えて**小麦**を育て、パンを焼く。畑は近くに十分な深さの水がないと乾く
9. 川から**水路**を掘って水を引き、**水門**で止め、**ポンプ**で高い所へ汲み上げる
10. 村人に頼まれた品を隣村まで**人力で運ぶ**。運んだ先が地図に載る
11. 2 つの村を**道でつなぐ**と荷運びが往復しはじめ、届いた村に**家が建つ**

## 実装している要素

- **地形生成** — シード決定論的。大陸ノイズ + 起伏 + リッジノイズで高さを決め、
  気温・湿度で 9 種のバイオーム（海 / 砂浜 / 平原 / 森林 / 砂漠 / 山岳 / 雪原 / タイガ / 湿地）に分ける。
  3D ノイズで洞窟を掘り、鉱石は鉱脈状に配置。木・草花・サボテン・サトウキビはチャンクを跨いで生える。
  陸は内陸ほど高くなり、その勾配に沿って**川**が海まで下る。川床は水面より必ず下まで
  掘り下げられるので、水路が途中で干上がって分断されることはない（後述）。
  川の水面はブロック単位に丸めず、最上段のセルを部分的に満たして表現するので、
  段差のないなめらかな下り勾配になる。
- **水** — ボクセルごとに水量を持つセルオートマトン。下へ落ち、横に均され、押し込まれた分だけ
  上へも戻る。静止した水は眠って計算コストがゼロになるので、海が広くても負荷にならない。
  詳しくは下の「水のしくみ」を参照。
- **天候** — 平常 → 大雨 → 平常 → 渇水 を 10 分ごとに繰り返す。天候が起きるのは**地図外の源流**で、
  水が流れ下るぶんだけ遅れて手元に届く（河口で最大 4 分）。渇水では川の水位が最大 1.8 ブロック
  下がって浅瀬と干上がった岸が出て、湧き水も細る。大雨では 0.8 上がるが、岸は必ず 1 ブロックの
  余裕を持って削られているので氾濫はしない。詳しくは下の「天候と水位」を参照。
- **村** — 20 チャンク四方に 1 つの割合で候補地を決め、平坦化した台地の上に道・井戸・
  家（4 職業・4 方向）・畑を建てる。家にはルートチェストと村人が配置される。
- **描画** — チャンクごとに面カリングしたメッシュを自前で組み立て、頂点に AO と
  スカイライト / ブロックライトを焼き込む。昼夜はシェーダのユニフォーム 1 つで切り替わるので
  時間が進んでもメッシュの作り直しは起きない。
- **光** — スカイライトとブロックライト（松明）の 2 チャンネルを flood fill で伝播。
  ブロックを壊す / 置くたびに差分だけ再計算する。
- **サバイバル** — 体力・満腹度・空腹によるダメージと自然回復、落下ダメージ、防具による軽減、
  無敵時間、ノックバック。死ぬと持ち物はその場に落ちる。
- **モブ** — ゾンビ / スケルトン（矢を撃つ）/ クモが夜の暗所に湧き、朝日で燃える。
  ブタ・ウシ・ニワトリ・ヒツジは昼の草地に湧き、攻撃されると逃げる。村人は村を歩き回る。
- **クラフト** — 検索できるレシピ一覧をクリックするだけ。材料は持ち物全体から自動で集められ、
  結果の置き場所がない時は材料を消費せずに断る。基本レシピは手元で、道具・防具・水利ブロックは
  作業台で解禁。木・石・鉄・ダイヤの 4 階層 × 5 種の道具、革と鉄の防具、パンなど。
- **精錬** — かまどで燃料を燃やして鉱石・食料・砂を加工。
- **農業** — クワで耕地を作り、水が近ければ湿った耕地に。小麦・ニンジン・ジャガイモが
  ランダムティックで成長する。乾いた耕地では作物は**育たず**、乾いたままだと 1 段階ずつしおれて
  やがて枯れる。灌漑は半径 4 マス以内の水深で判定するので、渇水で川が下がれば岸の畑は干上がる。
- **交易** — 村人は職業別の取引表を持ち、エメラルドを通貨に売買する。在庫には上限がある。
  村が発展すると品揃えが増え、必要量が下がり、在庫も増える。
- **村の産業と輸送路** — 村ごとに生産品が決まっており、村と村を歩ける道でつなぐと荷運びが
  往復して商品を運ぶ。届いた村は発展し、実際に家と畑が建つ。詳しくは下の「村と輸送路」を参照。
- **道案内** — 画面上部の方角バーに、出発地点・**最後に死んだ場所**・一番近い村の方向と距離が出る。
  右上のミニマップは読み込み済みのチャンクを俯瞰で描き、色は各ブロックのテクスチャの平均色から
  自動的に決まるので、地図と世界の見た目が食い違わない。
- **操作の自動化** — 掘る対象に応じてホットバーの最適な道具へ自動で持ち替え、1 マスの段差は
  ジャンプ無しで登る。どちらもポーズ画面で切れる。
- **設定** — ポーズ画面から描画距離（4〜12 チャンク）・マウス感度・コンパス・ミニマップ・
  天候の予報・道具の自動切り替え・段差の自動登りを変更でき、localStorage に保存される。
  現在のワールドのシードもここに表示され、クリックでコピーできる。
- **セーブ** — localStorage。シードと**変更したブロックの差分だけ**を保存するので、
  どれだけ探索してもセーブは小さいまま。チェスト・かまどの中身、村人の取引状況も保存される。
  プレイヤーが手を入れたチャンクの水量はランレングス圧縮して保存するので、作った貯水池は残る
  （水量を持たない旧セーブとは互換性がないため、セーブ形式は v2 に上げてある）。
  天候の時計も保存されるので、読み込み直しても季節は続きから進む。

## 水のしくみ

Timberborn のような治水の遊びを 3D ボクセル世界で成立させるため、水は**ボクセルごとに 0〜1 の
水量を持つセルオートマトン**として実装している（`src/world/waterSim.ts`）。1 秒に 10 回、動いている
セルだけを処理する。

- **落下** — 下のセルの空きに流れ込む。下が満杯なら、自分が満杯を超えている分（＝押し込まれた水）
  だけをさらに下へ押し込む。ただ積み重なっているだけの水は動かないので、**海は完全に静止して
  計算コストがゼロ**になり、水面が沈むこともない。
- **水平** — 自分より少ない隣接セルを局所平均まで一気に引き上げる。差の何分の一かずつ渡す方式に
  比べて桁違いに速く、12 ブロックの水路を数秒で水が走る。
- **上昇** — 満杯を超えたセルは上へ押し返す。だから水を押し込み続ければ、いったん谷底へ下ろして
  から反対側へ登らせる**逆サイフォン（伏越し）**が成立する。
- **眠り** — 動きが止まったセルはアクティブ集合から外れる。プレイヤーから 96 ブロックより遠い水も
  凍結され、戻ってくると再開する。
- **境界** — 未ロードのチャンクは壁として扱う。読み込み範囲はプレイヤーと一緒に動くので、
  そこで水を捨てると海が空になってしまうため。
- **生成された水は起こさない** — 川と海は生成された時点の姿を保ち、プレイヤーが手を入れるまで
  シミュレーションに乗らない。川は下流へ向かって水面が下がる「傾いた水面」なので、これを
  そのまま流体として解くと 1 枚の平らな池に均されてしまい、岸を這い上がる薄い水が残り続ける。
  川岸を 1 マス掘れば、その周りの水だけが目を覚まして穴を満たし、また眠る。

川の断面は、水面より必ず 1 マス高い岸で囲まれるように削られる。岸が水面より低いと、斜面の
段々に 1 マスぶんの水の膜が残り、川が丘を這い上がっているように見えてしまうため。この 1 マスの
余裕が、大雨のときに水位が上がっても氾濫しない保証にもなっている。

**水面はブロック単位に丸めない。** 川の水面高さは連続量で、最上段のセルだけを部分的に満たして
表現する（メッシャは角を共有する 4 列の水量を平均して面の高さを決めるので、そのまま滑らかな
斜面として描かれる）。丸めていた頃は数ブロック進むごとに水面が整数境界をまたぎ、検証用シードの
spawn 周辺だけで **113 段の階段**（同一水位の連結成分、中央値 42 セル）ができていた。さらに、
川の高さの元になる大陸ノイズは流下方向だけでなく**川幅方向にも**変化するため、水面が左右に
最大 3.5 ブロック傾いていた。いまは高さを**川筋の中心**で 1 回だけサンプリングする（経路ノイズの
勾配を 1 回ニュートン法で降りて中心線を求める）ので、左右の傾きは最大 0.065 ブロック / マスに
収まり、水面は岸から岸まで水平になる。

これで成立すること: ダム（ただのブロックの壁）で川をせき止める / 石で組んだ**水道橋**や暗渠で
水を対岸へ渡す / **水門**の開閉で流量を操る / **ポンプ**を縦に連ねて汲み上げる /
洞窟の水没 / 掘った穴に水が流れ込む。

| ブロック | 使い方 |
| --- | --- |
| 水源 | 自分の上のセルを満杯に保ち続ける。川の源流に自動生成される。壊して持ち運べる |
| 水門 | 右クリックで開閉。閉じれば壁、開ければ水も人も通る。縦に積めば開口の高さを変えられる |
| ポンプ | 下のセルから上のセルへ汲み上げる。縦に連ねれば任意の高さまで上がる |
| 排水口 | 入ってきた水を消す |
| バケツ | 満杯のセルから水を汲み、好きな所に置く |

## 天候と水位

Timberborn の季節サイクルにあたる仕組み（`src/world/weather.ts`）。**平常 → 大雨 → 平常 → 渇水**を
10 分（ゲーム内の半日）ごとに繰り返す。順番は固定なので渇水は必ず平常の次に来て、備える時間がある。
厳しさだけはシードで揺れる。

この仕組みの肝は**遅延**にある。天候が起きるのは地図の外の源流で、プレイヤーが見るのは
**そこを数分前に出た水**である。ある地点がどれだけ下流かは大陸ノイズから得られる「内陸度」で
決まり、河口では源流から 4 分遅れる。だから予報パネルには「ここはまだ平常、あと 3:42」と
「上流はすでに渇水」が同時に出る。その 3 分 42 秒が貯水池を満たす猶予になる。

- **水位** — 渇水で最大 1.8 ブロック下がり、大雨で 0.8 上がる。落差のほうが大きいのは、
  干上がっていく側が遊びとして面白いから。川床は水面の 3〜5 ブロック下にあるので、渇水でも
  流心には水が残り、縁が干上がって浅瀬と中州になる（完全には干上がらない）。
  海には季節がないので、水位は海面より下がらない。河口に近いほど落差が自然に小さくなり、
  川と海の境目に段差ができない。
- **湧き水** — 同じ内陸度・同じ遅延で出力が変わる。渇水では平常の 1/4 まで細るが止まりはしない。
- **既に読み込まれた川** — 生成された川はシミュレーションに乗せないので、季節に合わせて
  `src/world/riverFlow.ts` が水量を書き換える。1 回のスイープで数チャンクずつ、水面が
  0.08 ブロック動いたチャンクだけを対象にする。書き換える前に、その列が**前回書いた通りの水量か**
  を 1 セルずつ照合し、違えばプレイヤー（かシミュレータ）が触ったものとして手を出さない。
  だからダムも貯水池も掘った溝も季節に壊されない。橋を架けた列は橋の下までしか水が上がらない。
- **空と雨** — 大雨では空が灰色に寄って視程が詰まり、カメラの周囲を雨粒が落ちる（衝突判定なしの
  点群で、カメラと一緒に動き、下まで落ちると上へ巻き戻る）。渇水では空が白っぽく霞む。
  どちらも日照に比例するので、夜は明るくならない。

## 村と輸送路

Transport Fever のような物流の遊びを一人称のまま成立させる仕組み（`src/game/villages.ts`,
`roads.ts`, `transport.ts`, `questline.ts`）。どれも three.js に依存しないので Vitest から
そのままテストできる。

村そのものは今まで通りシードだけで決まる。この層が覚えているのは「その村に何が起きたか」だけで、
場所・生産品・名前はいつでもシードから導き直せるので、セーブに乗るのは稼いだぶんだけになる。

### 遊びの流れ

1. **村を見つける** — 台地（半径 38）に踏み込むと発見扱いになり、村名と生産品が分かる
2. **人力で運ぶ** — 村人が隣村への運搬を頼んでくる。取引画面の一番上に出るので、引き受けて
   歩いていく。納めると隣村も地図に載り、エメラルドと発展度が手に入る
3. **道を教わる** — もう一度話しかけると「道さえあれば我々が自分で運ぶ」と言う
4. **道を敷く** — 2 つの村を歩ける道でつなぐ。**シャベルの右クリック**で草や土をその場で
   踏み固めた土に変えられるので、材料を集めずに道を伸ばせる
5. **荷運びが歩く** — 在庫がたまると荷運びが出発する。近くにいれば実際に道を歩く姿が見え、
   すれ違える
6. **村が育つ** — 荷が届くと発展度が上がり、**実際に家と畑が建ち**、村人の取引表が広がる

### 道の判定

村どうしは最低でも 320 ブロック、実際には 400〜700 ブロック離れている。その距離を 1 マスも
欠かさず敷かせるのは苦行なので、**道は 20 マスまでとぎれてよい**。ただし緩めたぶん、
**間の地面が本当に歩けるか**を 1 マスずつ確かめる。

- 隣り合う列の高低差が 2 を超えたら不可（崖や段丘は跨げない）
- 地面が海面以下なら不可（海も、橋のかかっていない川床も跨げない。橋を架ければそこは道になる）

つまり「置く数は減らせるが、通れない所は通れない」。

**道と認めるのはプレイヤーが置いたブロックだけ**である。これは `World.edits`（＝セーブそのもの）
にしか存在しないので、判定はチャンクの読み込み状態と完全に無関係になる。読み込み済みのブロックを
見る方式だと、村から離れた瞬間に道が消えるうえ、地表に露出した天然の砂利鉱脈や山肌の石が
「誰も敷いていない道」として village をつないでしまう。

道と認めるブロック: 踏み固めた土 / 砂利 / 丸石 / 苔石 / 木材 / 石レンガ / 砂岩。
素の石と土は入れていない — 世界そのものがそれでできているので、天然の地面と区別がつかない。

### 接続状態の表示

とぎれを許すと「今つながっているのか」が見ただけでは分からなくなる。そこで調査結果は真偽値では
なく**両端からどこまで届いたか**を返し、3 か所に出す。

- **左のパネル** — 「未接続 / あと 128m」または「接続済み 384m / 荷運び 1」
- **コンパス** — 未接続なら `⋯` マーカーが**道がとぎれている所**を指す（目的地ではなく、直す場所）
- **ミニマップ** — 敷いた道を点で、とぎれている区間を破線で描く

### 荷運び

輸送の真実は**抽象的な時計**のほうで、荷運びはその見た目でしかない。プレイヤーが 64 ブロック
以内にいれば実体化して実際に道を歩き、その位置が進捗を決める（目の前で瞬間移動しない）。
離れれば実体は消え、進捗だけが時間で進む。道を掘り返されたら、輸送中の荷は出発村の在庫に戻る。

### 村の発展

発展した村の建物は、ワールド生成に手を入れるのではなく**普通の「記録される編集」として書く**。
`World.edits` は唯一の永続ブロック置き場で、チャンクを読み込むたびに `World.addChunk` が
必ず適用し直すので、これだけで建物はチャンクの出入りに耐える。書き込みは冪等なので、
留守のあいだに発展した村は、戻ってきたときに自分で建つ。

上書きしてよいのは空気と天然の地面（草・土・砂・雪・花・葉・水）だけに限っている。
プレイヤーが置いたチェストも壁も、村の元の家も触らない。失敗の仕方は「新しい建物に穴が空く」で、
「作った物が消える」にはならない。

## 割り切っていること

- 溶岩・レッドストーン・ネザーはない。
- 苗木がないので、木を切ってもその場所に木は生えてこない。
- 水車による動力はない。
- 川に「流れ」はない。水面はなめらかに下るが、水そのものは季節に合わせて書き換えられるだけで、
  流体としては動いていない。生成された川はプレイヤーが手を入れるまで静止しているので、
  水源から遠い場所で堰き止めても上流に水は溜まらない。貯水池を作るなら水源かポンプで
  水を送り込む（渇水のあいだは湧き水も細るので、そこが計画のしどころになる）。
- 川は**山地に差しかかると消える**。峡谷を刻んで山を貫くより自然に見えるほうを選んだので、
  山脈をまたぐ水系はそこで途切れる。1500 ブロック四方で測ると、川の水面の 94% は海までつながり、
  残りは山で切れた区間と内陸の閉じた水系になる。
- 生産チェーンは 1 段だけ。原料から加工品を作る中間の村はない。
- 道の種類による速度差はない。踏み固めた土でも石レンガでも荷運びの速さは同じ。
- 村の発展は 1 段階まで。衰退もしない。
- マルチプレイヤーはない。
- 音はない。

## 確認用の固定シード

地形生成をいじった時に「なんとなく違う世界になった」で済ませないために、確認はいつも同じ
ワールドで行う。シードは `voxelcraft`（数値では 2061350291）で、`src/game/seeds.ts` に定数として
置いてある。

- タイトル画面の**「検証用ワールド」**ボタンで一発で開く。
- URL に `?seed=...` を付けると、タイトルを経由せずそのシードのワールドが立ち上がる
  （例: `http://localhost:5173/?seed=voxelcraft`）。スクリーンショットや不具合報告をリンクで
  共有できる。
- ポーズ画面と `F3` に現在のシードが出る。ポーズ画面のシードはクリックでコピーできる。
- `src/test/seeds.test.ts` がこのシードのランドマークを固定している。スポーンが (8, 54, 0) で
  あること、そこから 16 ブロック以内に川があること、取引できる村が平坦な台地の上にあること。
  地形生成を変えるとこのテストが落ちるので、変更が意図的かどうかを必ず判断することになる。

## アーキテクチャ

描画に依存する層としない層を分けてある。`src/world` と `src/game` は three.js を import しないので、
Vitest から Node 上でそのままテストできる。

```
src/
  core/       ノイズ・PRNG・AABB 衝突といった土台
  world/      ブロック定義、チャンク、地形生成、川、天候、光、水シミュレーション、レイキャスト、ティック
  game/       プレイヤー、持ち物、クラフト、精錬、採掘、戦闘、満腹度、モブ、交易、セーブ
              村の産業（villages）、道（roads）、輸送（transport）、チュートリアル（questline）
  render/     テクスチャ生成、メッシャ、チャンク描画、空、エンティティ、エフェクト
  workers/    地形生成ワーカーとそのプール
  ui/         HUD・コンテナ画面・メニュー・入力（DOM オーバーレイ）
  test/       Vitest
```

地形生成は Web Worker のプールで並列に行い、メッシュ生成と光の伝播はメインスレッドで
フレームあたりの予算を決めて少しずつ進める。こうすることで隣接チャンクのデータを
スレッド間でやり取りせずに済み、ロード中もフレームが落ちにくい。

## 開発

```bash
npm run typecheck   # tsc --noEmit
npm run lint        # ESLint
npm test            # Vitest（描画に依存しないロジック）
npm run build       # 本番ビルド
npm run smoke       # Playwright で実際にブラウザを動かしてスクリーンショットを撮る
```

`npm run smoke` は起動中の dev サーバに対して実行する。タイトル画面 → ワールド生成 →
採掘 → レシピ一覧でのクラフト → 夜と戦闘 → 村と交易 →
**村の産業・道の接続判定・荷運び・村の発展** → 農業 → 洞窟と松明 → **川に水道橋を架けて水門で操る** →
ポンプで汲み上げる → 潜って溺れかける → 死亡とリスポーン → セーブしてリロード → URL のシード指定、
までを通しで動かし、`screenshots/` に画像を書き出す。ワールドは固定シードなので、出力される
座標や数値は毎回同じになる。

```bash
npm run dev &
npm run smoke -- http://localhost:5173/ screenshots
```

### デバッグ用コンソール API

ゲーム中はブラウザのコンソールから `voxelcraft` が使える。

```js
voxelcraft.give('diamond_pickaxe')   // アイテムを配る
voxelcraft.setTime(0.7)              // 0=日の出 0.25=正午 0.5=日没 0.75=真夜中
voxelcraft.gotoVillage()             // 一番近い村へ飛ぶ
voxelcraft.gotoRiver()               // 一番近い川の岸へ飛ぶ
voxelcraft.waterDepth(x, y, z)       // その柱の水深（ブロック）
voxelcraft.waterSurface(x, z)        // その柱の水面の高さ（小数、乾いていれば null）
voxelcraft.pourWater(x, y, z, 3)     // 3 ブロック分の水を注ぐ
voxelcraft.weather()                 // 今の季節・上流の季節・到達までの遅れ・水位差
voxelcraft.setWeather('drought')     // 次の渇水（大雨 / 平常）のピークへ時計を飛ばす
voxelcraft.setWeatherSeconds(1800)   // 天候の時計を秒で直接動かす
voxelcraft.findCave()                // 近くの洞窟へ潜る
voxelcraft.spawnMob('zombie')        // 目の前にモブを出す
voxelcraft.toggleFly()               // 飛行の切り替え
voxelcraft.villages()                // 知っている村（名前・生産品・発展段階・在庫）
voxelcraft.village()                 // 今いる村、なければ最寄り
voxelcraft.quest()                   // チュートリアルの進み具合
voxelcraft.questStep('accept')       // 受注 / 納品 / 道の話 を進める
voxelcraft.gotoQuestTarget()         // 今の目標へ飛ぶ
voxelcraft.buildRoad()               // 目標の 2 村間に道を敷く（手作業だと数百ブロック）
voxelcraft.routes()                  // 輸送路（接続状態・距離・不足距離・荷運びの数）
voxelcraft.porters()                 // 今出ている荷運びの数
voxelcraft.roadIndex()               // 索引済みの道の列と改訂番号
voxelcraft.advanceTransport(600)     // 輸送の時計を秒で進める
voxelcraft.discoverNearby()          // 周囲の村をまとめて発見済みにする
```
