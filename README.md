# VoxelCraft

TypeScript と three.js で作った、ブラウザで動くボクセルサンドボックスゲーム。
自動生成される地形を掘り、素材を集め、道具を作り、夜に湧く敵をしのぎ、畑を耕し、村人と取引する。
町にはそれぞれ工場と**欲しい物**があり、原料は自分で資源のそばに建てた**一次産業**から出る。
**停留所を置いて路線に並べる**と荷運びが往復しはじめ、荷が届いた町は集落から都市へと育ち、
運賃がプレイヤーに入る。道をどれだけ敷いても、路線が無ければ荷は 1 個も動かない。
水はボクセル単位で量を持つ流体シミュレーションで、海から水路を引き、堰き止め、水門で流れを操れる。

外部の画像アセットは一切使わない。ブロックとアイテムのテクスチャは起動時に Canvas 2D で
手続き的に描かれ、1 枚のアトラスに合成される。

```bash
npm install
npm run dev      # http://localhost:5173 を開く
```

**公開版: https://kamocyc.github.io/claude-web-test-24/**（`main` に入ったものが自動で上がる）

## 遊び方

| 操作 | 動作 |
| --- | --- |
| `W` `A` `S` `D` | 移動（歩行 8.6 ブロック/秒。3 マスまでの段差はジャンプ無しで登る） |
| `Space` | ジャンプ（水中では浮上。岸に向かって泳げばそのまま陸に上がれる） |
| `Shift` | **ダッシュ（17.2 ブロック/秒＝歩行の 2 倍）** |
| `Ctrl` | **ゆっくり歩く**（1.8 ブロック/秒。設置対象のブロックを開かずに置く） |
| マウス移動 | 視点（最初に画面をクリックしてカーソルを固定） |
| 左クリック | 採掘（長押し）/ 攻撃 |
| 右クリック | 設置・使用・食べる・作業台/かまど/チェストを開く・村人と取引 |
| 右クリック長押し（シャベル） | **歩きながら道を敷く**。カーソルとその周囲 8 マスが道になり（3×3 なので上下左右でつながる）、カーソルが飛んだぶんは自動で埋まる |
| 右クリック（線路敷設ツール） | **始点→終点をクリックして、その間をなめらかな線路でつなぐ**（ボクセルグリッドとは無関係。既存の線路の端を狙えばその角度に合わせる） |
| 左クリック（線路敷設ツール） | 敷設をやめる／狙っている線路を撤去する |
| 敷いた線路の上 | **歩ける。** 曲線も勾配もそのまま踏める（支柱は見た目だけで素通り） |
| `1`〜`9` / ホイール | ホットバー選択 |
| `E` | 持ち物（レシピ一覧・防具） |
| `L` | 交易台帳（町の生産品・需要・産業・路線の区間の一覧） |
| `N` | **路線表**（停留所を路線に並べる。並べるまで荷は 1 個も動かない） |
| `H` | **遊びかた**（チュートリアル・目標一覧・道の判定・路面・荷車・キー一覧） |
| `[` `]` | **ゲーム速度**を下げる／上げる（×1〜×16。世界の時計だけが速くなる。キーの位置ではなく**打たれた文字**で見ているので、`[` が別の位置にある JIS 配列でも効く） |
| `F3` | デバッグ表示（座標・バイオーム・シードなど） |
| `C` | **デバッグ: 全アイテムの棚**（ポーズ画面で「全アイテム無限」を入にしているときだけ） |
| `G` | 座標へワープ（`X Z` か `X Y Z` を入力。Y を省くと地面の上に降りる） |
| 右クリック（停留所） | **地面に停留所を置く**。停留所を狙えば撤去して持ち帰る |
| 右クリック（産業設置具） | **足もとの資源を調べ、足りていれば一次産業を建てる** |
| `F` | 見ている建物をその町の集荷所にする |
| `R` | **見ている所（20 マス先まで）から足もとまで一気に道を敷く** |
| `Esc` | 画面を閉じる（カーソルは固定したまま）/ ポーズ |

クラフトは**マスに材料を並べる方式ではない**。レシピ一覧から作りたい物をクリックすると、
持ち物のどこにある材料でも自動で消費される。Shift+クリックで作れるだけまとめて作る。
材料が足りないレシピも不足分を表示したまま並ぶので、一覧がそのままレシピブックになる。

### 最初の 10 分

0. 持ち物には**木材 32・土 32**が入っている（新しい世界だけ。橋を渡し、床を張り、道の窪みを
   埋めるための最低限で、道具は入っていない）
1. 木を殴って**原木**を取る → `E` を開いて木材・棒・**作業台**をクリックで作る
2. 作業台を置いて開くと道具と防具のレシピが解禁される。木のツルハシ → 石を掘って**石の道具**
3. **石炭**と**松明**を作り、暗い場所を照らす（明るい場所には敵が湧かない）
4. 日が暮れる前に囲いを作るか洞窟に隠れる。ゾンビ・スケルトン・クモが湧く
5. 動物を狩って肉を焼き、**満腹度**を保つ。空腹だと体力が減る
6. **鉄鉱石**を石のツルハシで掘り、かまどで精錬して鉄の道具・防具へ
7. **村**を探す。チェストに物資があり、村人とエメラルドで取引できる
8. クワで土を耕し、種を植えて**小麦**を育て、パンを焼く。畑は近くに十分な深さの水がないと乾く
9. 海や池から**水路**を掘って水を引き、**水門**で止め、**ポンプ**で高い所へ汲み上げる
10. 村人に頼まれた品を隣の分村まで**人力で運ぶ**。運んだ先が地図に載る
11. **停留所**を 2 つ置き、`N` の路線表で 1 本の路線に並べる。**ここまでやって初めて便が出る** —
    道をどれだけ敷いても、路線が無ければ荷は 1 個も動かない
12. 2 か所を**道でつなぐ**と荷運びが往復しはじめ、届いた町に**家が建つ**。運賃が入る
13. `L` で台帳を開くと、**町の工場が何の原料で止まっているか**が出る。町は何も掘らないので、
    原料の出どころはこれから自分で建てる
14. **産業設置具**を作って、石炭や鉄の**露頭**・砂地・森・広い草原を右クリック。個数と密度が
    足りていれば**一次産業**が建つ。そこに停留所を置き、町までの路線をひく
15. 道を**砂利や石畳で舗装し直す**と荷運びが速くなり、一度に運ぶ量も増える
16. 鉄が余ってきたら**線路敷設ツール**と**レール**を作り、停留所どうしを**線路でつなぐ**。届いた
    時点で**列車**が走り、それまでの 4 倍を、一番速い速さで運ぶ。線路は道ではないので、道が
    通らない所も通る

## 実装している要素

- **地形生成** — シード決定論的。大陸ノイズ + 起伏 + リッジノイズで高さを決め、
  気温・湿度で 9 種のバイオーム（海 / 砂浜 / 平原 / 森林 / 砂漠 / 山岳 / 雪原 / タイガ / 湿地）に分ける。
  3D ノイズで洞窟を掘り、鉱石は鉱脈状に配置。**石炭と鉄はまれに地表に露頭として顔を出す**ので、
  尾根から見て一次産業を建てる場所を探せる。木・草花・サボテン・サトウキビはチャンクを跨いで生える。
  陸は内陸ほど高くなるので、海岸は海岸らしく、山は内陸にできる。
- **水** — ボクセルごとに水量を持つセルオートマトン。下へ落ち、横に均され、押し込まれた分だけ
  上へも戻る。静止した水は眠って計算コストがゼロになるので、海が広くても負荷にならない。
  詳しくは下の「水のしくみ」を参照。
- **町** — 20 チャンク四方に 1 つの割合で候補地を決め、平坦化した台地の上に**街路の格子**を敷き、
  区画ごとに用途を決めて建てる。真ん中に広場、その周りに**商店**（街路に面した壁がまるごと硝子）、
  外側に**住宅**（唯一の切妻屋根）、風下の一角に**工場**（丸石と煙突 2 本、町で一番背が高い）。
  家にはルートチェストと村人が配置される。
- **描画** — チャンクごとに面カリングしたメッシュを自前で組み立て、頂点に AO と
  スカイライト / ブロックライトを焼き込む。昼夜はシェーダのユニフォーム 1 つで切り替わるので
  時間が進んでもメッシュの作り直しは起きない。
- **光** — スカイライトとブロックライト（松明）の 2 チャンネルを flood fill で伝播。
  ブロックを壊す / 置くたびに差分だけ再計算する。
- **採掘** — 硬さと道具で速さが決まるが、**どんなブロックも 1 秒以内に壊れる**。良い道具ほど
  速いという順番はそのままで、遅い側だけを 1 秒に向けて詰めてある。掘るのは遊びの本体では
  ないので、素手で 17 秒かかるかまどのようなものは無くした。
- **サバイバル** — 体力・満腹度・空腹によるダメージと自然回復、落下ダメージ、防具による軽減、
  無敵時間、ノックバック。死ぬと持ち物はその場に落ちる。
- **モブ** — ゾンビ / スケルトン（矢を撃つ）/ クモが夜の暗所に湧き、朝日で燃える。
  ブタ・ウシ・ニワトリ・ヒツジは昼の草地に湧き、攻撃されると逃げる。村人は村を歩き回る。
- **クラフト** — 検索できるレシピ一覧をクリックするだけ。材料は持ち物全体から自動で集められ、
  結果の置き場所がない時は材料を消費せずに断る。基本レシピは手元で、道具・防具・水利ブロックは
  作業台で解禁。木・石・鉄・ダイヤの 4 階層 × 5 種の道具、革と鉄の防具、パンなど。
- **精錬** — かまどで燃料を燃やして鉱石・食料・砂を加工。
- **農業** — クワで耕地を作り、水が近ければ湿った耕地に。小麦・ニンジン・ジャガイモが
  ランダムティックで成長する。乾いた耕地では作物は**育たず**、乾いたままだと 1 段階ずつしおれて
  やがて枯れる。灌漑は半径 4 マス以内の水深で判定するので、畑は水のそばに作るか、水路を引く。
- **交易** — 村人は職業別の取引表を持ち、エメラルドを通貨に売買する。在庫には上限がある。
  町が発展すると品揃えが増え、必要量が下がり、在庫も増える。
- **停留所と路線** — **道があるだけでは荷は 1 個も動かない。** プレイヤーが停留所を置き、`N` の
  路線表でそれを順に並べて初めて便が出る。徒歩の便も列車も同じ規則で動く。**車両は選ばない** —
  区間ごとに、実際に何がつないでいるか（線路 / 幅 3 マスの道 / 道）で走るものが決まる。
- **一次産業と資源** — 町は何も掘らない。原料は**プレイヤーが資源のそばに建てた産業**から出る。
  産業設置具で足もとを調べ、鉱脈と露頭の**個数と密度**が足りていれば建つ。枯渇しない。
- **2 段の供給連鎖** — 産業（原料）→ 町の工場（加工品）→ 別の町の住宅と商店（消費）。工場に
  よっては原料が 2 種類要る（硝子 = 砂 ＋ 石炭）ので、1 本の路線では足りない町がある。
  荷が届いた町は 4 段階まで発展し、実際に建物が増える。詳しくは下の「町と輸送路」を参照。
- **道を良くする 4 つの手と、その先の 1 つ** — **つなぐ**（1 マスも空けない・段差 1 マス以内・
  頭上 2 マス）、**舗装する**（速さ）、**幅 3 マスに広げる**（荷車が出て 3 倍運ぶ）、
  **平らにする**（登りは時間を食う）。その先が**線路を敷く**ことで、これだけは道の改良ではない
  — 別の道すじを引く仕事で、届いた時点で**列車**が走り、速さも量も上がる。
  遠回りは運賃が増えないので損になる。うまくいっていない所は世界に光の柱で出る。
- **遊びかた画面（`H`）** — チュートリアルの段・目標一覧・停留所と路線・一次産業の条件・
  町の段階・道の判定と敷き方・路面の表・荷車と列車の条件・**荷が出る条件**・勾配と遠回り・
  キー一覧が 1 画面に出る。**実装の定数から
  組んである**ので、数字を調整しても説明のほうが追いつく。
- **ゲーム速度** — ポーズ画面か `[` `]` で ×1〜×16。**世界の時計だけ**が速くなり、移動も採掘も
  受けるダメージもいつも通り。物流は待つ遊びなので、待つほうを縮められるようにしてある。
- **道案内** — 画面上部の方角バーに、出発地点・**最後に死んだ場所**・一番近い町の方向と距離が出る。
  右上のミニマップは読み込み済みのチャンクを俯瞰で描き、色は各ブロックのテクスチャの平均色から
  自動的に決まるので、地図と世界の見た目が食い違わない。
- **操作の自動化** — 掘る対象に応じてホットバーの最適な道具へ自動で持ち替え、**3 マスまでの段差**は
  ジャンプ無しで登る。段差は低い方から順に試すので、天井の低い所で 1 マスの縁石が登れなくなることはない。
  どちらもポーズ画面で切れる。
- **現在地の表示とワープ** — 画面左下に常時 XYZ・チャンク・向き・**FPS** が出る（ポーズ画面で
  切れる）。FPS を `F3` の裏だけでなくここにも出すのは、「重いのは自分の環境か、それとも今の
  場面か」を訊きたくなるのが、歩きながら座標を見ている時と同じだからである。
  `G` で開く入力欄に座標を入れるとその場所へ飛ぶ。デバッグ表示の `XYZ 12.3 / 71.0 / -45.6` を
  そのまま貼り付けても通る。
- **難易度** — ポーズ画面で **平和 / やさしい / ふつう / 難しい**を切り替えられる。変えた瞬間から
  効く。動くのは「世界がプレイヤーに何をするか」だけで、同じツルハシは同じ速さで石を掘る。

  | | 敵 | 受けるダメージ | 同時に出る敵 | 飢え |
  | --- | --- | --- | --- | --- |
  | 平和 | 出ない（既にいる敵も消える） | 0 | 0 | 死なない・体力が毎秒 0.5 戻る |
  | やさしい | 出る | ×0.5 | 14 体 | 死ぬ |
  | ふつう | 出る | ×1 | 28 体 | 死ぬ |
  | 難しい | 出る | ×1.5 | 42 体 | 死ぬ |

  「ふつう」の数値は難易度が無かった頃とまったく同じなので、既存のワールドの手応えは変わらない。
- **設定** — ポーズ画面から難易度・描画距離（4〜12 チャンク）・マウス感度・コンパス・ミニマップ・
  目標と輸送路・道しるべ・座標の表示・道具の自動切り替え・段差の自動登りを変更でき、
  localStorage に保存される。
  現在のワールドのシードもここに表示され、クリックでコピーできる。
- **セーブ** — localStorage、および**ファイル**（ポーズ画面の「ファイルに書き出す」で
  `voxelcraft-<シード>-<日時>.json` として保存し、タイトルの「セーブファイルを開く」または
  ポーズ画面の「ファイルから読み込む」で開く。localStorage はブラウザにひとつしか無く、
  履歴を消せば一緒に消えるので、持ち出せる形も用意してある）。
  シードと**変更したブロックの差分だけ**を保存するので、
  どれだけ探索してもセーブは小さいまま。チェスト・かまどの中身、村人の取引状況も保存される。
  プレイヤーが手を入れたチャンクの水量はランレングス圧縮して保存するので、作った貯水池は残る
  （水量を持たない旧セーブとは互換性がないため、セーブ形式は v2 に上げてある）。

## 水のしくみ

Timberborn のような治水の遊びを 3D ボクセル世界で成立させるため、水は**ボクセルごとに 0〜1 の
水量を持つセルオートマトン**として実装している（`src/world/waterSim.ts`）。1 秒に 10 回、動いている
セルだけを処理する。

- **落下** — 下のセルの空きに流れ込む。下が満杯なら、自分が満杯を超えている分（＝押し込まれた水）
  だけをさらに下へ押し込む。ただ積み重なっているだけの水は動かないので、**海は完全に静止して
  計算コストがゼロ**になり、水面が沈むこともない。
- **水平** — 自分より少ない隣接セルを局所平均まで一気に引き上げる。差の何分の一かずつ渡す方式に
  比べて桁違いに速く、12 ブロックの水路を数秒で水が走る。
- **上昇** — 満杯を超えたセルは上へ押し返す。だから水を押し込み続ければ、いったん谷底へ下ろして
  から反対側へ登らせる**逆サイフォン（伏越し）**が成立する。
- **眠り** — 動きが止まったセルはアクティブ集合から外れる。プレイヤーから 96 ブロックより遠い水も
  凍結され、戻ってくると再開する。
- **境界** — 未ロードのチャンクは壁として扱う。読み込み範囲はプレイヤーと一緒に動くので、
  そこで水を捨てると海が空になってしまうため。
- **生成された水は起こさない** — 海は生成された時点の姿を保ち、プレイヤーが手を入れるまで
  シミュレーションに乗らない。海岸を 1 マス掘れば、その周りの水だけが目を覚まして穴を満たし、
  また眠る。

**水面はブロック単位に丸めない。** 水量は連続量で、最上段のセルだけを部分的に満たして表現する
（メッシャは角を共有する 4 列の水量を平均して面の高さを決めるので、水が流れ落ちる段や引いていく
水際が、整数の階段ではなくなめらかな面として描かれる）。

これで成立すること: ダム（ただのブロックの壁）で水路をせき止める / 石で組んだ**水道橋**や暗渠で
水を対岸へ渡す / **水門**の開閉で流量を操る / **ポンプ**を縦に連ねて汲み上げる /
洞窟の水没 / 掘った穴に水が流れ込む。

| ブロック | 使い方 |
| --- | --- |
| 水源 | 自分の上のセルを満杯に保ち続ける。壊して持ち運べる。川の源流に自動生成されていたが、川を無くしたので**新しい世界には生成されない**（古いセーブに残っているものは今も湧く） |
| 水門 | 右クリックで開閉。閉じれば壁、開ければ水も人も通る。縦に積めば開口の高さを変えられる |
| ポンプ | 下のセルから上のセルへ汲み上げる。縦に連ねれば任意の高さまで上がる |
| 排水口 | 入ってきた水を消す |
| バケツ | 満杯のセルから水を汲み、好きな所に置く |

## 町と輸送路

Transport Fever のような物流の遊びを一人称のまま成立させる仕組み（`src/game/villages.ts`,
`industry.ts`, `lines.ts`, `sites.ts`, `roads.ts`, `transport.ts`, `questline.ts` と、表示側の
`src/ui/routePanel.ts`, `linePanel.ts`, `ledger.ts`）。計算側はどれも three.js に依存しないので
Vitest からそのままテストできる。

町そのものは今まで通りシードだけで決まる。この層が覚えているのは「その町に何が起きたか」だけで、
場所・生産品・名前はいつでもシードから導き直せるので、セーブに乗るのは稼いだぶんだけになる。

**この遊びの背骨は 2 つある。**

**1. 道があるだけでは荷は 1 個も動かない。** 動かすのは**路線**で、路線とは、プレイヤーが置いた
**停留所**を順番に並べたものである。舗装しつくした街道でも、そこに路線が無ければただの道。
これは徒歩の便も列車も同じで、例外はない。

**2. 町は何も掘らない。** 町にあるのは工場で、工場は原料を加工品に変える。原料の出どころは
**プレイヤーが資源のそばに建てた一次産業**だけ。だから供給は 2 段になる:

```
一次産業（原料）→ 町の工場（加工品）→ 別の町の住宅と商店（消費）
```

どちらの段も、路線をひくのはプレイヤーである。

### 遊びの流れ

1. **町を見つける** — 台地に踏み込むと発見扱いになり、町名・工場の加工・**需要**が分かる。
   このとき、**その町の少し先に小さな集落（分村）が建つ**。チュートリアルの相手役で、
   最初に見つけた町だけが持つ（詳しくは下の「チュートリアルの分村」）
2. **人力で運ぶ** — 村人がその分村への運搬を頼んでくる。取引画面の一番上に出るので、引き受けて
   歩いていく。**積み荷はその場で町が持たせてくれる**（落としてしまったら、元の町で足りない
   ぶんだけ受け取り直せる）。行き先はまだ見つけていない場所なので、**目標パネルに方角と距離が
   出て、コンパスに ⚑ の印が付く**。納めると分村も地図に載り、エメラルドと発展度が手に入る
3. **運送を教わる** — もう一度話しかけると「停留所と路線さえあれば我々が自分で運ぶ」と言う
4. **停留所を置く** — 停留所を手に持って地面を右クリック。町の中に 1 つ、相手側にも 1 つ。
   町から 72 マス以内に置けばその町の停留所になる。停留所どうしは 8 マス以上離すこと
5. **路線をひく** — `N` で路線表を開き、新しい路線に 2 つの停留所を順に加える。**車両は選ばない** —
   区間ごとに、実際に何がつないでいるかで走るものが決まる（線路なら列車、幅 3 マスの道なら
   荷車、それ以外は徒歩）。停留所 2 か所の路線は往復し、3 か所以上なら循環する
6. **道を敷く** — 2 つの停留所を**1 マスも空けずに**つなぐ。**シャベルを持って右クリックを
   押したまま歩けば**足もとが道になり続けるので、材料も、1 クリック 1 ブロックも要らない。
   遠くを指して **`R`** を押せば、そこから足もとまでが一気に道になる。町の街路が 29 ブロック先
   まで伸びているので、実際に敷くのはその外側だけ。段差は 1 マスまで、頭上は 2 マス空いている
   こと。通らなかった所はその場でトーストが言う
7. **荷運びが歩く** — 在庫がたまると荷運びが出発する。近くにいれば実際に道を歩く姿が見え、
   すれ違える
8. **一次産業を建てる** — 町の工場は原料が届くまで何も作らないので、次にやることはその原料を
   掘る場所を作ること。**産業設置具**を持って地面を右クリックすると足もとを調べ、資源が
   足りていれば産業が建つ。そこに停留所を置き、町までの路線をひく
9. **町が育つ** — 荷が届くと発展度が上がり、**実際に建物が建ち**、村人の取引表が広がる
10. **道を良くする** — 舗装すれば速くなり、**幅 3 マスに広げれば荷車が出て 3 倍運ぶ**。
    段差を均せば速くなり、まっすぐ通せば時間あたりの運賃が増える。その先が**線路**で、
    **停留所どうしを線路でつなげば列車が走り、4 倍運ぶうえに一番速い**（線路だけは材料が要る）
11. **次の路線を選ぶ** — 台帳（`L`）を見て、欲しがっている町と作っている町を結ぶ。
    原料が 2 種類要る工場（硝子・鍛冶・灯り）を動かすには、別々の産業から 2 本ひくことになる

**`H` を押すと「遊びかた」画面**が開く。チュートリアルの段、そのあとの目標一覧、停留所と路線、
一次産業の条件、町の段階、道の判定と敷き方、路面の表、荷車の条件、勾配と遠回りの罰、キー一覧が
1 画面に出る。中身は**実装の定数から組んである**ので、数字を調整しても説明のほうが勝手に追いつく。

### 停留所と路線 — プレイヤーが設計するもの

以前は、**道がそのまま路線だった**。最後の 1 ブロックを置いた瞬間に交易が始まり、決めることも
名前を付けることも無かった。つまり網は**地形から導かれる結果**であって、誰かが設計したものでは
なかった。輸送の遊びは設計のほうにある。

いまはプレイヤーが**停留所**を置き、それを**路線**に並べる。**並べるまでは、道の上でも線路の上でも
何ひとつ動かない。** 路線の無い道はただの道であって、便ではない。

| | |
| --- | --- |
| 停留所を置く | 停留所を持って地面を右クリック。丸石の 3×3 と看板の柱が建つ（見た目だけ） |
| 撤去 | 置いた停留所を狙ってもう一度右クリック。呼んでいた路線からも外れる |
| 何に付くか | **町は置いた時に決まり、あとで変わらない**（72 マス以内）。**産業は近さで決まる** — 停留所を先に置いて産業を後から建てるのが普通なので |
| 路線をひく | `N` の路線表で路線を作り、停留所を順に「加える」。1 路線 8 か所まで |
| 走る向き | 停留所 2 か所なら往復。3 か所以上なら**循環**する（端で折り返すと真ん中だけ 2 倍来てしまうため） |
| 同じ停留所 | 続けて 2 回は呼べない（自分から自分への区間になる）。間を空ければ何度でも呼べる |
| 車両 | **選ばない。** 区間ごとに、実際に何がつないでいるかで決まる |

**車両を選ばせないのは、答えがもう出ているからである。** 道を敷いて、そのうえで改めて「荷車」を
選ばせるのは同じ質問を 2 回することになる。何を走らせるかは、何を建てたかで決まる。

路線を編集しても、**区間が同じままなら走っている荷はそのまま**である（積んだ量も、運んだ総量も）。
消えた区間の荷は積み地に戻る — 路線をいじるのは時間の損であって、荷の損ではない。

### 一次産業 — 原料の出どころ

**産業設置具**を持って地面を右クリックすると、周囲 10 マス・上 8 / 下 12 マスの柱を全部数えて、
そこに何が建てられるかを答える。**個数と密度の両方**が足りていないと建たない。

| 産業 | 掘り出す物 | 要る資源 | 個数 | 密度 |
| --- | --- | --- | --- | --- |
| 鉄鉱山 | 鉄鉱石 | 鉄鉱石 | 24 | 4% |
| 炭鉱 | 石炭 | 石炭鉱石 | 32 | 5% |
| 砂採取場 | 砂 | 砂・砂岩 | 140 | 35% |
| 林業所 | 原木 | 原木・葉 | 120 | 20% |
| 農場 | 小麦 | 草・耕地 | 200 | 60% |

**地中の鉱脈も、地表に出ている露頭も、同じように数える。** 露頭というのは、地表に剥き出しに
なった石炭や鉄の斑（`src/world/generation/features.ts` の `OUTCROPS`）で、「ここを掘れば出る」
という目印である。丘の斜面に見えたら、そこは鉱脈の上端だと思ってよい。

**枯渇しない。** 掘り出す速さは建てた時の資源の多さで決まり（最大 2.5 倍）、あとから変わらない。
1 か所の在庫は 48 個まで。満杯になっていたら、それは路線が来ていないということ。
産業どうしは 40 マス以上離すこと — 同じ資源で二重取りはできない。

建った産業は、砂利の作業場と丸石の小屋、そして**小屋の倍の高さの煙突**になる。尾根から見つけ
られる形にしてあるのは、資源を探す遊びが「歩いて見る」遊びだからである。

**建たなかったときは、その理由が出る。** 断り文句は「ここには何も無い」で終わらせない —
建つはずだった判定と同じ 1 回の走査から、一番惜しかった産業を名指しし、**2 つのうちどちらの
条件を落としたか**を数字つきで言う。この 2 つは歩く方向が違うからである。

| 出る文 | 意味 | 次にすること |
| --- | --- | --- |
| `炭鉱には量が足りない（21 / 32 個。密度は足りている）` | 濃さは十分、鉱脈が小さい | もっと大きい鉱脈を探す |
| `砂採取場には散らばりすぎ（密度 12% / 35%。量は足りている）` | 資源はあるが薄く広がっている | 濃く固まっている所の**真上**に立つ |
| `炭鉱には足りない（15 / 32 個、密度 2% / 5%）` | どちらも足りない | もっと濃く固まった所を探す |
| `ここには何も無い` | どの資源も 1 個も無い | 露頭・砂地・森・広い草原へ |
| `砂採取場 1 まで 22m しかない（産業どうしは 40m 以上）` | 既にある産業の資源 | 40 マス以上離れる |

**建てた産業を見ると、種類・掘る物・在庫・産出倍率・出荷数が画面の上に出る。** どの産業も
同じ小屋なので、種類が読めるのはここと交易台帳（`L`）だけである。停留所がまだ無いか、満杯の
まま集めに来ていないかも、その 1 行が言う。

**撤去は、建てたのと同じ 1 つの動作。** 建てた産業に向けて（あるいはその上に立って）
産業設置具を右クリックすると、産業が消えて設置具が戻る。停留所と駅と同じ規則で、
「置いたものは、置いた道具で剥がせる」。小屋・煙突・木箱のうち**設置時のブロックのまま残って
いるものだけ**を消すので、上に何か建てていればそれは残る。均した作業場の地面も残る — 丘を
削ったのはプレイヤーの仕事で、それを勝手に戻すのは嘘になるからである。

### 需要と加工の連鎖

町は自分が作れない物を欲しがる。**求めている品を届けると発展度は 3 倍**になるので、
「どことどこを結ぶか」がそのまま設計になる。欲しい物は発展するほど増えていく
（既に欲しがっていた物は減らない）。

町はどこも工場の町で、加工は 6 通りある。

| 工場 | 原料 | 作る物 |
| --- | --- | --- |
| パン | 小麦 | パン |
| 製材 | 原木 | 木材 |
| 砂岩 | 砂 | 砂岩 |
| 灯り | 原木 ＋ 石炭 | 松明 |
| 硝子 | 砂 ＋ 石炭 | 硝子 |
| 鍛冶 | 鉄鉱石 ＋ 石炭 | 鉄インゴット |

**原料が全種類そろうまで 1 個も作らない。** 砂をいくら積んでも、炉に入れる石炭が無ければ硝子の
町は止まったままである。だから 2 原料の町は「路線 1 本で足りる相手」ではなく、はじめて
**網**を設計する理由になる。台帳では原料切れの町に印が付き、何が足りないかを名前で言う。

荷運びは**帰り道も空ではない**。出発した側が到着した側の生産品を欲しがっていれば、それを積んで
帰る。互いに補い合う 2 か所を結ぶと、1 本の道が 2 本ぶん働く。

**行き先が町でない区間には荷を積まない。** 産業どうしをつないでも降ろす先が無いので、何も動か
ない。路線表と台帳はその状態を「町も産業も無い」と名指しする。

### 町の中 — 住宅・商店・工場

町は「1 品目を作る 1 つの在庫」ではなく、**それぞれ別のことを欲しがる建物の集まり**である
（`src/game/townEconomy.ts`）。建物には用途があり、用途は**シードから導かれる**ので保存されない。

| 用途 | 中にいる人（集落） | すること |
| --- | --- | --- |
| **住宅** | 4 | 人が住む。働きに出る。隣の町へ行きたい人が生まれる |
| **商店** | 2 | 人が来ると品物が売れる |
| **工場** | 3 | 人が来るとその町の原料を使う |

段階が上がるごとに、中にいる人は 1 人ずつ増える。そして**育った町ほど通りがにぎやかになる** —
働きに出る人は住宅 1 軒あたりの割合で出るので、住宅が増えれば同時に歩いている人も増える。

**この層が回すのはひとつの輪である。**

```
住宅に人が住む → 通勤で商店・工場へ行く → 客が来た商店が品物を欲しがる
→ プレイヤーが運ぶ → 町が育つ → 住宅が増える → 人が増える
```

肝は 3 行目である。**人が来た建物だけが品物を使う。** 誰も通ってきていない商店は何も欲しがらず、
何も売らない。だから「人が動く」ことがそのまま「需要が生まれる」ことであり、
人の移動をわざわざ計算する理由になっている。

- **住宅が欲しがる物**: パン / 松明 / 木材のうち 2 つ（建物ごとに固定）
- **商店が欲しがる物**: 硝子 / 砂岩 / 鉄インゴットのうち 2 つ
- **工場が欲しがる物**: その町の原料**すべて**。2 種類要る町の工場は 2 種類とも待つ — 片方だけ
  届いても動かないので、そこは半分ではなく零である
- 1 つの建物が持てるのは 1 品目につき **8 個**まで。倉庫ではないので、届けた物はいずれ切れて
  また欲しがる

**品物が届かない町は止まらない — 遅くなる。** 人の出入りも旅立ちも 2.5 倍かかるようになるだけで、
育った町が縮むことはない（README「割り切っていること」の「町は衰退しない」はそのまま生きている）。
そして**この層は発展度を勝手に配らない**。町が育つのは、これまでどおり**プレイヤーが運んだとき
だけ**である。

**建物を見ると、その建物が何を待っているかが出る。** 原料が来ていない工場と、客が来ていない
商店は、外から見ると同じ形をしていて、プレイヤーにとっては全く別の仕事である。
台帳（`L`）には、立っている町の建物が用途・人数・待っている物つきで並ぶ。

#### 人の移動 — 通勤と旅

町の中の**通勤**は、`t` が 0 から 1 へ進むただの数である。プレイヤーが 48 ブロック以内に
いるときだけ村人モブが湧いてその数を追いかける。**モブは view であって、通勤を止めることは
できない** — 荷運びと荷の関係とまったく同じ規則で、理由も同じ（`src/game/transport.ts` の
冒頭に長く書いてある）。だから誰も見ていない町でも人は働きに出ているし、
戸口に引っかかった村人が町を止めることはない。

町の外へ行きたい人は**荷と同じ「品目」**として運ばれる（`passenger`。アイテムではないので
手には持てない）。運賃も発展度も、荷とまったく同じ経路を通る。

**荷が先で、人は空いた便に乗る。** 出す物がある町の便が駅の行列に取られることはなく、
人が乗るのは「本来なら空で帰るはずだった便」だけである。だから路線に人を乗せても、
運べる荷は減らない。**線路の場合、人を積んだ列車は貨車ではなく客車を連ねる** —
外から見て違いが分かるのはそこだけなので。

道が掘り返されて便が消えたときは、人は駅の行列に戻る（荷が町の在庫に戻るのと同じ）。

#### 何を保存して、何を保存しないか

**町の中については何も保存しない。** 人数は「用途 × 町の段階」から導かれ、食料庫の中身と
通勤の列は、また埋まるまでの 1 分ぶんの価値しかない。開き直した町は少しお腹が空いているだけ
である。

**保存するのは、シードから導き直せない物だけ。** 町単位の在庫（`stock` / `inputStock`）と
発展度、**プレイヤーが置いた停留所と、並べた路線**（`network`）、**建てた一次産業**
（`industries`）である。道と線路は編集としてすでに保存されているので、区間の形は読み込み時に
もう一度踏査する。

**セーブ形式は 3 になり、2 のワールドは開かない。** 2 には停留所も路線も産業も無く、経済は
「道がつながれば勝手に始まる村どうしの取引」だった。それを新しい世界に読み込む正直なやり方は
無い — 荷はどの路線も呼ばない場所にあり、町はもう自分が作っていた物を作らない。半分だけ
変換して見せるより、断って新しい世界を始めてもらうほうを取った。

### 路面の質

道は「つながっているか」だけでなく**何で舗装されているか**が効く。速度は敷いた区間の
（距離 ÷ 所要時間）で測るので、長い土の道に石レンガを 10 マス足しても大して変わらない —
舗装は一区間ずつ積み上げる仕事になる。

| 路面 | 速さ | 1 回の積み荷 |
| --- | --- | --- |
| 踏み固めた土 | 1.0 倍 | 2 |
| 砂利 / 砂岩 | 1.2 倍 | 3 |
| 丸石 / 苔石 / 木材 | 1.45 倍 | 5 |
| 石レンガ | 1.7 倍 | 6 |

舗装はシャベル 1 本でいくらでも敷けるので、「どこを先に良くするか」は時間の問題でしかない。
**費用の問題になるのは線路だけ**である（下の「鉄道」）。呼び名の一番上「鉄路」はどの舗装でも
届かない — **線路の路線だけがそこに乗る**。

道は長いほど荷運びの数も増える（320 ブロックごとに 1 人、最大 3 人）ので、遠い町を結んでも
便数が距離なりに落ちきることはない。

### 荷車 — 幅 3 マスの道だけを通る

**全区間が幅 3 マス**（上の 5c）なら、荷運びの代わりに**荷車**が出る。**一度に運ぶ量は 3 倍**。
速さは変わらない — **速さは舗装、量は幅**と役割を分けてあるので、「どちらを先に直すか」が
そのまま設計になる。

| | |
| --- | --- |
| 条件 | 路線の全区間が幅 3 マス |
| 見返り | 積載 3 倍 |
| 広げ方 | **シャベルの掃き敷きは 3×3** なので、できあがった道の上をもう一度歩けば広がる。`R` は 1 マス幅のまま（つなぐための道具） |
| 狭くなったら | 路線は**切れずに徒歩へ降格**する。荷は消えない |
| どこが狭いか | 世界に**琥珀色の光の柱**、パネルに「荷車: 幅が足りない（東へ 84m）」 |

町の街路は最初から幅 3 なので、広げるのは町と町の間だけ。見本ワールドの道も幅 3 で敷いてあり、
起動直後から荷車が走る。

### 鉄道 — 線路敷設ツールで敷く曲線

舗装も幅も、いつかは打ち止めになる（石レンガが最後の路面で、幅 3 が最後の広さ）。その先が
**線路**である。ただしこれは**道の改良ではない**。線路はブロックではなく、道の索引にも乗らず、
地形にも触らない。**もう一本の道すじ**であり、**道がまったく無い 2 つの停留所でも、線路が
つながっていれば荷は動く**（もちろん、路線に並べてあれば、の話である）。

**始点をクリックし、終点をクリックすると、その間が一本のなめらかな曲線になる。**
ボクセルグリッドとは何の関係も無い。

| | |
| --- | --- |
| 道具 | **線路敷設ツール**（作業台で**鉄インゴット 3 ＋ 棒 2**）。持っているあいだ、左右のクリックはこの仕組みだけに使われる |
| 敷き方 | **右クリックで始点 → もう一度右クリックで終点。** 左クリックは敷設の取り消し、敷設していなければ狙っている線路の撤去 |
| 端の向き | **クリックしたときのプレイヤーの向き（yaw）。** 見上げ／見下ろしは狙う点を決めるだけで、線路の角度には入らない |
| 既にある線路 | 端を狙えば**位置も向きも勾配もその端に合わせる**。継ぎ目に折れができない |
| 寸法 | **枕木を含めた幅 2.0 マス、軌間 1.2 マス** |
| 地形 | **一切変えない。** 空中を通ってよく、浮いた区間には自動で支柱が立つ |
| 材料 | 作業台で**鉄インゴット 6 ＋ 木材 2 → レール 16**。1 マスにつき 0.5 本、撤去すると半分返る |
| 断る形 | 半径 6 マスより急な曲がり／20% より急な勾配／3 マス未満・96 マス超の長さ／始点の向きの後ろ |

**材料が要るのは線路だけである。** ほかの路面はシャベル 1 本でいくらでも敷けるので、「どこを
先に良くするか」は時間の問題でしかない。線路に材料を付けると、それが初めて**費用**の問題に
なる。そして鉄インゴットを作るのは鍛冶の町で、その町は鉄鉱石と石炭の両方を待っている。
つまり**鉄道を敷きたいと思った時点で、鉄鉱山と炭鉱を建てて 2 本の路線を引く理由が生まれる** —
網が自分の材料を運ぶようになる。

#### 駅 — 線路の両端に建てないと荷は動かない

**線路をつないだだけでは、荷は動かない。** 線路の端に**駅**を建てて、はじめてそこが積み下ろし
の場所になる。町のそばを線路が通っているだけの状態は、町のそばを道が通っているだけなのと
同じで、その町には何もしていない。

| | |
| --- | --- |
| 作り方 | 作業台で**木材 6 ＋ 鉄インゴット 1 → 駅 1**。1 つの路線には 2 つ要る |
| 建て方 | 持って**線路の端を狙い、右クリック**。建った駅をもう一度右クリックすると撤去して持ち帰る |
| 建てられる場所 | **線路の端ならどこでも。** 曲線の継ぎ目も端なので、長い線路の途中に駅を作りたければそこで一度切って敷く |
| 町に届く条件 | 駅が**町の中心から 48 マス以内**。建てたときに「どの町の駅になったか」が出るので、届いていなければその場で分かる |
| 見た目 | 線路の片側に**ホーム**、その上に屋根。**出荷待ちの荷が木箱として積まれる**（最大 6 個ぶん） |
| 駅が無いとき | その端に**桃色の光の柱**、パネルに「列車: 線路の端に駅が無い（東へ 30m）」 |

**なぜ駅が要ることにしたか。** 線路がつながった瞬間に荷が動くと、鉄道は「道の一番良いやつ」
でしかない。積む場所と降ろす場所を建てさせると、鉄道は**点と点を結ぶもの**になる — 線路は
どこを通ってもよく、意味を持つのは端の 2 つだけ、という形になる。ついでに、**完成して見える
のに動かない**という一番わかりにくい状態が消える: 駅が無ければ、無い場所に光の柱が立つ。

**古いセーブ。** 駅ができる前に敷いた線路は、**線路はそのまま・駅は 0 個**で開く。その路線は
未接続になるが（道があれば道へ降格する）、桃色の光の柱が両端を指すので、駅を 2 つ建てれば
元どおり走る。

#### 列車 — 線路が停留所と停留所をつないだとき

**両方に駅があり**、その 2 つが線路でつながっていれば、荷車の代わりに**列車**が走る。
（それでも、その 2 か所を 1 本の路線が呼んでいなければ、走るものは何も無い。）

| | |
| --- | --- |
| 条件 | **駅**が**両方の停留所から 48 マス以内**にあり、その 2 つの駅が線路でつながっていること |
| 見返り | **積載 4 倍**、かつ**一番速い（2.2 倍）**。速さと量が同時に上がるのはこれだけ |
| 道との関係 | **無い。** 道が無くても走るし、道が良くても線路の路線の速さは変わらない |
| 呼び名 | 路線は全区間まとめて**「鉄路」**（2.2 倍）。舗装のように区間ごとに測らない |
| 戸口まで | 駅から集荷所の戸口までは**歩き**で、その距離はパネルの「戸口まで」に出る（道の路線と同じ扱い） |
| 積み込み | 戸口から駅までは**荷運びが運ぶ**。ホームで列車に持ち替わり、向こうの駅でまた荷運びが戸口まで運ぶ |
| 編成 | 積んでいる量ぶんの**貨車をつないで**走る。**1 両 9 個・満載 4 両**。機関車だけなら空荷で帰る便 |
| 途切れたら | 路線は**切れずに道へ降格**する（道があれば荷車か徒歩、無ければ切れる）。荷は消えない |
| どこで途切れたか | 世界に**紫の光の柱**、パネルに「列車: 線路が途切れている（東へ 84m）」 |

**「届く」のを戸口ではなく停留所そのものからの距離にしてある理由。** 町の外周は家である。
戸口まで線路を引かせると、家のあいだを縫って敷くことになる。駅が町のはずれにあるのは
この世界にかぎった話ではない。歩くぶんは**運賃ではなく所要時間**として毎便に乗る
ので、駅を近くに作る動機はちゃんと残る。

**積み込みは「持ち替え」として見せている。** 荷そのものは相変わらず 0 と 1 のあいだの数で、
それを描いているモブが**どこにいるかで人か列車かが変わる**だけである。町のなかを歩いている
あいだは荷運び、ホームから先は列車、向こうのホームからまた荷運び。待ち時間も積み込み時間も
無い — 時計はひとつのままで、絵だけが変わる。荷を止める仕組みを増やすと、見ている人の目の前
でだけ線が止まるという、以前に一度やって失敗したことをまたやることになる。

#### 列車に乗る

**列車には貨車のほかに客車が必ず 1 両つながっている。** 荷が 0 でも付いてくる — 稼がない
車両だが、鉄道を敷いた人がそれに乗れないのはおかしい。

| | |
| --- | --- |
| 乗りかた | **駅のホームは客車の床と同じ高さ**。停まっている列車の横から、開いている戸口へ歩いて入る |
| 乗れる面 | **客車の床・客車の屋根・貨車の荷・機関車の屋根**。曲線でも振り落とされない |
| 当たり判定 | **上に乗れる面だけ。** 壁も柱も見た目である（高架の支柱と同じ扱い） |
| 降りかた | ジャンプ。壁にぶつかる位置に運ばれそうなときは、**列車のほうが置いていく** |

**乗っている人は「車両のどこに立っているか」で覚えてある。** 世界の座標を「車両が動いたぶん
だけ動かす」のでは、曲線で外側に振り落とされる。車両の前後・左右という 2 つの数で持って
毎フレーム置き直すと、**列車が曲がれば一緒に曲がる** — 部屋の中を歩いているのと同じになる。
上下も同じで、勾配を登る列車の床は 1 フレームで 0.3 マス以上せり上がることがあり、
「足もと 0.35 マス以内の面を探す」という普段の規則では追いつかない。

**車両の寸法は線路から出している。** 車輪は軌間（1.2）に、車体は枕木の幅（2.0）から手のひら
1 枚ぶん内側に。数字を別に書くと、どちらかを直した日にずれる。**ホームの高さと客車の床の
高さも同じ 1 つの数**である — ホームとは、車両の床と同じ高さの台のことだからである。

**編成は「機関車が通った跡」に沿って置いてある。** 満載の列車は 20 マスを超えるが、
線路は半径 6 マスまで曲がれる。機関車の後ろに箱を一列に並べる描き方だと、曲がるたびに
車両が線路の外へ振り出される。だから機関車は 0.4 マスごとにパン屑を落とし、各車両は
その跡を自分のぶんだけ遡った所に立つ — **文字どおり機関車が走った線の上**にいるので、
どんな形の曲線でも外れない。この描き方は biarc のことを何も知らなくてよい。

**貨車の数は積荷そのものである。** 1 両が「鉄路の質で荷運び 1 人ぶん」＝ 9 個なので、満載の
列車はちょうど 4 両 — `TRAIN_LOAD` が約束している 4 倍を、数字ではなく長さで見せている。
在庫が少ない町から出る便は 1 両で出るし、片方しか品物を欲しがっていない区間は帰りが機関車
だけになる。丘の上から編成を見れば、その路線がどれだけ稼いでいるかが分かる。

**路線がまとめて 1 つの速さなのは、線路が舗装ではないからである。** 道は区間ごとに何を敷いた
かが違うので、質は「距離 ÷ 所要時間」で測るしかない。線路はどこも同じ物で、谷を渡る高架も
平地の直線も同じ速さで走る — だから 1 本の路線に 1 つの数字を出す。`roadGrade` の一番上に
あった「鉄路」は、これでどの舗装からも届かない呼び名になった。

**線路の上は列車も歩く。** 荷を運んでいるモブは高架の上を走るので、`Mob` にもプレイヤーと
同じ「立てる面」を渡してある（列車だけ。荷運びと荷車には渡していない — 高架に用が無い）。


#### 曲線の解きかた

**形は「平面の biarc ＋ 弧長上の 3 次曲線」である。** 平面線形と縦断線形を分けるのは実物の
線路の作法だが、ここで効いたのは実装の側の四つだった。**曲率の下限が半径 2 つを比べるだけで
厳密に判定できる**こと。**弧長が閉じた式で出る**ので、枕木が等間隔に並ぶのがタダになること。
両端の接線が共線なら**厳密な直線**に退化すること。そして**終点が始点の接線の後ろにあると
ソルバが負の根を返す**ので、尖点やループを黙って描く代わりに理由を言って断れること。
3 次ベジエ（Create MOD がやっている形）だと、このうち後ろ 2 つが数値サンプリングと
場合分けになる。

代償は**継ぎ目で曲率が飛ぶ**こと — 緩和曲線が無い。Create も同じで、軌間 1.2 マスの線路で
これに気付く人はいない。

**勾配はプレイヤーのピッチから取らない。** 地面をクリックするとき人は 30〜60 度見下ろして
いるので、ピッチを勾配にすると線路が毎回空へ跳ね上がる。何もつながっていない端は**水平に出て
水平に着き**、高低差は途中の S 字が吸収する。吸着した端だけが、その端の勾配を継ぐ。

**敷いた線路は上を歩ける。** ただし甲板だけで、支柱は見た目である。

仕掛けは掃引の外側に置いた 1 パスである。`aabb.ts` の `moveAxis` は衝突を
**`Math.floor` で整数のブロック面へスナップ**して解決する — コライダ（`isSolidAt`）は真偽を
返すだけの神託で、接触面の位置は「一番近い整数平面」と決め打ちされている。だから
**`y = 64.37` の甲板には、あの仕組みのままではどうやっても乗れない**。

甲板の当たり箱を掃引に足す案は捨てた。`moveAxis` の手術が要るうえ、**傾いた甲板が
5cm 刻みの階段になる**からである。`moveAxis` はそれを壁として扱うので、上り坂を歩くあいだ
毎フレーム段差登りを通ることになり、しかも `autoStep` を切ってあると段差登りの門に届かないので
**ゆるい勾配が登れなくなる**。代わりに、掃引はブロックに任せ、**甲板は後から 1 度だけ乗せる**。
甲板を「高さの場」として持ち、線分の上で**高さを補間する**ので、階段ではなく本物のスロープになる。

拾う範囲は足もとから **0.35 マス**（最急勾配 0.2 × 最速 × 最長フレーム ＝ 0.11 の 3 倍、かつ
段差 1 マスの 1/3）。それより高い高架には**跳んで乗る**（落ちてくる側の判定が受け止める）。
落下ダメージの前に置いてあるので、高架に落ちれば痛い。

**モブと落ちている物には渡していない。** 高架に登る理由も、登ってしまった荷運びを降ろす手立ても
無いので。落とした物は高架から下へ落ちる。

**下書きは首の動きに追いてくる。** 始点を置いたあと、曲線は「狙っている点」と「今の yaw」の
純関数として毎フレーム解き直される。だから**その場で振り向けば曲がり方が選べる**。
始点を置いているあいだ、十字の下に**長さ・勾配・曲がり**が出る:

```
長さ 32.4 マス
勾配 上り 12%（高低差 +4.0 マス）
曲がり 右 半径 24.0 マス
```

**勾配は上りか下りかを、曲がりは左右を必ず言う。** 「急すぎる」だけでは、首をどちらへ振れば
ゆるくなるのかが分からない。断られる形のときも同じ場所に理由が赤で出る —
`勾配が急すぎる（上り 45%、20% まで）` / `曲がりが急すぎる（右 半径 4.2 マス、6 マス以上必要）`。
断られた形についても曲線は解けているので、**建たない形も説明はされる**。
断られる形のときは線路の形をやめて**赤い一本線**になる — 色より形のほうが「これは建たない」を
速く伝えるので。空いている端には水色の光の柱が立つ（吸着できる場所が見えないと、
吸着は偶然でしか見つからない）。

**支柱は未ロードのチャンクの上には立たない。** `heightAt` がそこでは -1 を返すので、
誰も生成していない地面の上に橋脚を生やすより、チャンクが来てから生やすほうを選んである。

**保存しているのは端だけ**である。節点の位置・向き・勾配だけを書き、曲線は読み込み時に解き直す
（`SavedRoute` が道に対してしているのと同じ取引）。ソルバは閉じた式で決定的なので、
戻ってくるのは「似た形」ではなく同じ形になる。**セーブ形式の版は上げていない**ので、
既存のワールドはそのまま開く（線路が 1 本も無い世界として、正しく）。

例外が 1 つある。**途中で割った区間だけは継ぎ目の座標も書く。** 等接線 biarc の半分は
それ自身が等接線 biarc ではないので、端だけから解き直すと**元の形から最大 1.7 マスずれる**。
縦断は 3 次 Hermite なので部分区間がそのまま再現され、こちらは何も足していない。

**手っ取り早く見るには**コンソールで `voxelcraft.give('track_tool')`、ホットバーで持って
地面を右クリック。`voxelcraft.sampleTrack()` は直線 1 本と曲線 2 本を足もとから一息に敷く。

### 分岐 — 途中から割って枝を出す

**線路の途中を狙って敷きはじめると、そこで線路が割れて枝が出る。** 端まで戻る必要はない。
狙っているところで割れると分かるときは、十字の先に**桃色の目印**が出る（つなげられる端に出る
水色とは別の色である。片方は今ある線路を変える操作で、もう片方は違う）。

節点は「向き 1 つと符号」ではなく**ポートの列**を持っている。ポートは「そこから線路が出て
いく向きと勾配」で、普通の継ぎ目は正反対の 2 つ、分岐器は 3 つを持つ。分岐が作れなかったのは、
節点が接線を 1 組しか書けなかったからである。

**走れる向きは規則ではなく幾何から落ちてくる。** ポート `p` から入るとは `−tangent(p)` の
向きに走っていることで、ポート `q` から出るとは `+tangent(q)` の向きに走ることだから、
通り抜けられるのは `dot(−tangent(p), tangent(q)) > cos(31°)` のときだけになる。普通の継ぎ目は
内積 1 で必ず通れ、引き返しは −1 で必ず弾かれ、**分岐器では本線の片側からしか枝に入れない** —
実物の背向き分岐が、そう書いたからではなく出てくる。列車が後退して枝に入ることはないので、
向きを間違えて敷いた枝は経路として使われない。

| | |
| --- | --- |
| 割れる場所 | 区間の端から 3 マス以内では断る（片側が短すぎてソルバに蹴られるため） |
| 枝の向き | 本線から **31°** まで。それを超えると分岐ではなく別の線路が横切っているだけなので断る |
| 枝の勾配 | **本線の勾配を継ぐ。** 分岐は列車が進路を選ぶ場所であって、登りはじめる場所ではない |
| 枝の本数 | 1 つの節点に 1 本まで（両渡りは無い） |
| 撤去 | 枝を抜いても節点は残る。同じ場所から別の枝を敷き直せる |

**経路探索は曲線の本数ではなく長さで選ぶ。** 状態は「節点」ではなく**「節点と、入ってきた
ポート」**で、上の内積規則を辺を広げるときに当てるので、**引き返す経路は最初から作られない**。
長さで測るのは近道のためでもあるが、それ以上に**同点の決着**のためである — 本数で数えていた
頃は同点を辺の挿入順で決めており、辺の id はリロードで振り直されるので、**同じワールドを
開き直すたびに荷の通る道が変わりうる**状態だった。

**線路の端の目印は、その端で空いている向きごとに 1 つ出る。** 分岐は「端」でも「途中」でも
あるので、まだ空いている向きがどれかは目印の数で分かる。

### 信号 — 閉塞と、詰まったとき

**信号と信号のあいだが 1 つの閉塞区間で、そこに入れる列車は 1 本だけである。** 前が空くまで、
後続は信号の手前で止まって待つ。

| | |
| --- | --- |
| 作る | 作業台で**鉄インゴット 2 ＋ 木材 2 → 信号機 2** |
| 置く | 持って線路を狙い右クリック。**途中を狙えばそこで割ってから建つ**ので、どこにでも置ける |
| 撤去 | 建った信号をもう一度右クリックすると持ち帰る |
| 灯 | **緑＝隣の区間が空いている／赤＝列車が入っている／黄＝詰まっている** |

**信号を 1 つも置いていない線路は、今までとまったく同じに動く。** 区間は辺の union-find で
作られ、**信号の付いていない節点を越えて連結される**ので、信号が 0 本なら網全体が 1 つの区間に
なる。そして**どの信号にも接していない区間は取り締まらない**ので、誰も誰も待たない。
1 本置いた瞬間に、その両側が意味のある閉塞になる。既存のワールドが壊れないのはこの 1 行である。

**信号は節点に付ける（辺には付けない）。** 辺の id はリロードで振り直されるが節点 id は
保存されるので、辺に付けた信号は次に開いたとき線路の別の場所に現れる。

**transport はグラフを知らない。** 区間は不透明な数で、`TrackWay` が「どこで区間が変わり、
どの数になるか」だけを返す。荷は境目を跨ぐ前に「向こう側の数を誰か持っているか」を訊き、
持っていればその場に留まる。占有表は**路線ごとではなく網全体で 1 つ**である — 2 つの路線が
同じ線路を共有するのが分岐の目的だから。

**時計を止められるのは他の荷だけで、モブには決して止められない。** 荷運びが戸口に引っかかって
路線が止まる、という以前の失敗を繰り返さないための線引きである。

**単線で向かい合ったら本当に詰まる。自動では解かない。** 互いに相手の欲しい区間を持ち合うので、
どちらも動けなくなる。10 秒待たされた時点で「詰まった」と判定し、**両方の信号が黄色くなり、
そこに黄色い光の柱が立ち、パネルが**「列車: 信号待ちで詰まっている（東へ 84m）— 待避線が要る」
**と言う**。解き方は 2 つ、信号を 1 つ抜いて区間をつなげるか、分岐で待避線を作るか。
後者が本来のやり方である。**どちらを待たせるかを決める仕組みは無い**（それはダイヤであって、
ここには無い）。

### 荷が出る条件 — つながっているのに動かないとき

| | |
| --- | --- |
| **路線が要る** | **停留所 2 つを 1 本の路線に並べるまで、荷は 1 個も動かない。** 道の出来には一切関係がない |
| 生産するのは | **発見済み（一度足を踏み入れた）町だけ**。1 個あたり 6 秒 ÷（1 + 0.35 × 発展度）、在庫の上限 64 |
| 町の工場は | **原料が全種類そろうまで 1 個も作らない**。作れない間は時間も溜め込まない |
| 一次産業は | 見ていなくても掘り続ける。在庫 48 個で満杯になって止まる（＝路線が来ていない印） |
| 出発の条件は | **在庫 1 個以上**。満載は待たない（あれば一度に運ぶ量まで積むだけ） |
| どちらから出るか | **在庫のあるほうの端から**。相手が欲しがっている品を持っている側が優先 |
| 降ろす先 | **町だけ。** 行き先が産業や何も無い停留所の区間には、そもそも荷を積まない |
| 荷運びの数 | 320 ブロックごとに 1 人、最大 3 人。前の 1 人が 15% 進むまで次は出ない |
| 同じ町の複数区間 | **在庫を分け合う**。取る順番は毎更新でずれる |

**「在庫のあるほうから出る」は、以前は違った。** 荷は `route.from` からしか出ず、向きは
シードの格子順、実質くじ引きで決まっていた。**町はどこも原料が届くまで何も作らない**ので、

- 往路は出発側の在庫を要求する → 在庫は 0
- 出発側の原料は**帰り便**でしか届かない → 帰り便は往路の後

という循環で、**その区間は永久に動かなかった**。向きが逆に決まれば何事もなく動くので、
症状は「つないでも始まらない**ときがある**」になる。区間は 2 つの停留所を結ぶ線であって
一方通行の管ではないので、**在庫のあるほうから出す**ようにした。

つながっているのに何も動かないときは、左のパネルがどれに当たっているかを言う:
「出荷待ち — 在庫 0（1 個たまれば出発する）」「○○に材料が無い — 石炭が届けば動き出す」
「○○にまだ入っていないので生産していない」「○○には町も産業も無い — 積む物も降ろす先も無い」。

### 運賃と目標

荷が届くたびに**運賃がエメラルドでプレイヤーに入る**（積み荷 × **集荷所どうしの直線距離**、
求められていた品なら 1.5 倍）。
持ち物がいっぱいなら次の到着まで持ち越されるので、消えることはない。これが村人との取引を
回す元手になる。

チュートリアルを終えると**目標**が順に出る（輸送路を 2 本 / 工房に原料を届ける / 舗装する /
一次産業を建てる / 工場に原料を届ける / 町を育てる / 3 つの町をつなぐ / 街道を敷く /
2 原料の工場を動かす / 都市をつくる / 鉄道を敷く）。
達成するとエメラルドが入り、左のパネルと台帳に次の目標が出る。

### 交易台帳（`L`）

町の一覧（工場の加工・原料の在り高・在庫・求めている物・発展度・距離）、産業の一覧、区間の一覧
（区間・品・接続状態・路面・積み荷・荷運び・累計）が 1 画面に出る。網を設計するための画面で、
コンパスやパネルでは見えない「どこが余っていてどこが足りないか」はここで読む。

### 道の判定 — 「つながっている」の正確な定義

**道は 1 マスも空けずに続いていなければならない。** 以下が実装されている規則のすべて。

**1. 何が「道の列」か**（3 条件すべて）

- そのブロックが `World.edits` にある ＝ **プレイヤー（または町の増築）が置いた物**。
  生成されただけのブロックは、見た目が何であれ道ではない
- ブロック id が道の材質である: 踏み固めた土 / 砂利 / 砂岩 / 丸石 / 苔石 / 木材 / 石レンガ。
  素の石と土は入れていない — 世界そのものがそれでできているので天然の地面と区別がつかない。
  **線路はこの表に無い**。線路はブロックではないので、道の索引はそれを見たことすらない
  （かつては「レール」という路面があったが、曲線の鉄道に置き換えて消した）
- **真上の 2 マスが非固体**。荷運びの背丈は 1.95 マスなので、1 マスしか見ていなかった頃は
  **木の枝が張り出した下の道**が索引に通ってしまい、頭をぶつける道を「つながっている」と
  呼んでいた（砂に埋もれた道が索引から外れるのも同じ条件）

1 マスの (x, z) につき 1 本だけ記録される。空の列に道ができたときは**いちばん高い有効な高さ**、
**すでに道を持っている列はその高さのまま**である。後者は町の増築のためにある: 町が道の脇で
地面を持ち上げて 10 マス上に自分の通りを敷くと、その列には有効な道が 2 つできる。高いほうを
採ると、プレイヤーが敷いた道の途中が町の玄関先まで持ち上がり、**誰も歩けない段差**が道の
真ん中にできる（実際、町が育った瞬間に区間が切れていた）。列が持っている道が道でなくなった
とき — 掘り返された、舗装し直された、上を塞がれた — に限って、記録は動く。

**2. 2 つの列が「1 本の道」である条件**

**上下左右のとなりにあり、高低差が 1 以内**であること。これだけ。斜めはつながらない。
20 マスまでのとぎれを許していた頃の規則は撤去した。

**斜めを外したのは、そこから面倒が全部出ていたから。** 斜めを認めると幅が数えられない
（斜めに走る幅 3 の道は 1 列あたり隣接 4 マスで、1 列に絞られた道の 6 マスより*少ない*）ので、
幅の判定を「進行方向」付きにするしかなく、その向き付きの判定が今度は
**荷車に穴を斜めからすり抜けさせた**。上下左右だけにすれば、幅は「左右 1 マスずつ」という
文字どおりの意味になり、抜け道は無くなる。

代償は、**角度のついた道が階段状になり、およそ 1.4 倍長くなる**こと。
`R` と見本ワールドの道はもともと自動で敷くので、階段に折るのは道具の側の仕事にした。

高低差は 2 ではなく **1**。荷運びの跳躍は `JUMP_SPEED² / (2·GRAVITY) ≒ 1.11` ブロックしか
上がらないので、**2 マスの段差は「索引がつながっていると言い、歩く者が登れない道」**だった。
そこで荷運びは壁に向かって跳び続け、抽象の時計だけが先へ進み、7 ブロック遅れた所で座標を
書き換えられていた — これが「道の途中で人が詰まるとワープする」の正体である。
規則のほうを歩ける物に合わせた。

**3. 町の側**

町の街路は*生成された*ブロックなので索引されない。代わりに**街路の格子そのものを幾何から
問い合わせる**（`districts.ts` の `onStreet`）。ある道の列が町に**接している**とは、その列が
街路のマスであるか、いちばん近い街路のマスの**隣**にあること。つまり**道は町の外周の街路に
届けばよく、中心まで来る必要はない**。

以前は「村＝中心から東西南北に伸びる十字」という近似で合成していた。腕が 4 本しか無いので、
**斜めから来る道は中心近くまで来て初めて接する**という妙な挙動があった。街路が格子になった今は
外周がぐるりと一周しているので、どの方角から来ても同じ距離で着く。

**分村は「町」ではなく「場所」として扱う**（`townPlace` が `town: null` を返す）。分村には
街路が無いので、格子を持たせると建っていない街路で踏査が終わる。詳しくは「チュートリアルの分村」。

**4. 町の増築は道を塞がない**

町が発展して建物が建つとき、**道が通っている区画には建てない**。区画のどこか 1 列でも
道の索引が持っていれば、その区画は諦めてほかの候補に回す（1 段階の候補は 8 区画ある）。

以前は「道の列の上（と、その上 2 マス）には固体ブロックを置かない」という譲り方をしていた。
道は残るのだが、**壁と床にだけ道の形の穴が空いた家**が建つ。敷いた本人にとっては
「町に道を食われた」であって、道が残っていることは慰めにならない。区画ごと譲るほうが正しい。

道の列そのものは、どのブロックからも守られる（区画を均すときの空気と土を含む）。
砂利は**プレイヤーが敷く舗装**でも**世界が作る地面**でもある唯一のブロックなので、
「天然の地面なら上書きしてよい」という規則だけでは砂利道を守れない。

**5. 探索 — 最短ではなく最速**

出発側に接している列を起点に、道の列だけを辿るダイクストラ探索。到着側に接している列に
着いたら接続。**地形は一切見ない** — 続いている道は海の上でも谷の上でも通る。道の上の橋は
「誰かが置いたブロック」なので、そこは道の列そのものである。上限 4096 列。

辺の費用は**秒**である:

```
費用(a→b) = (水平距離 + |Δy| × CLIMB_COST) ÷ 路面の速さ
```

`CLIMB_COST = 1.5`、つまり**登り 1 マスは平地 1.5 マスぶんの時間**。だから

- **平らな回り道が階段状の近道に勝つ**（同じ 2 本の道があれば、荷運びは平らなほうを通る）
- **段差の多い道は質が落ちる**。石レンガで舗装しても 1 マスごとに上下していれば
  「けもの道」まで落ちる。これが縦方向のペナルティの見える形で、直し方は「均す」である

**5b. 遠回りのペナルティ — 運賃は直線距離で払う**

所要時間は道の長さで決まるが、**運賃は集荷所どうしの直線距離**で決まる。以前は道の長さで
払っていたので、**うねった道ほど儲かっていた**。今は遠回りは「同じ運賃・長い時間・少ない便数」
になる。パネルと台帳は `遠回り ×1.34` を出す（1.15 を超えたときだけ）。

**5c. 幅 — 荷車が通れるか**

同じ探索を、**幅の足りる列だけ**に絞ってもう一度走らせる。ある列が幅を満たすとは、
**進行方向の左右 1 マスずつにも道の列がある**こと（高低差 1 以内）。つまり道幅 3 マス。
判定するのは**一歩の両端**で、荷車が入る列と出る列の両方に左右がなければならない。

道が上下左右にしか進まないので、「進行方向に直交する」＝「もう一方の軸」である。
`runRoad` も**その一歩ぶんの向き**に対して帯を敷き、角では**入る向きと出る向きの両方**に敷く
（片方だけだと、そこは荷車が曲がれない角になる）。

**穴があれば、そこで荷車は止まる。** 斜めに逃げる道が無いので、これは今や幅の規則の
当たり前の帰結であって、特別な検査ではない。

町の街路は生成物なので索引に無い。だから**町の街路に接している列は無条件に幅を満たす**扱いに
する（そうしないとどの道も両端で必ず狭くなる）。

**6. 「あと Xm」の意味**

未接続のとき、両端それぞれについて**相手にいちばん近い自分の道の列**（道が 1 本も無ければ
町の街路の縁）を求め、その 2 点の**直線距離**を返している。道が続きものになった今、
1 ブロックはちょうど 1m ぶんなので、パネルと台帳は距離と個数の両方を出す
（「あと 368m・道 368 個ぶん」）。斜めに置いて近道はできないので、この個数は**下限**である —
斜めに離れた 2 点をつなぐ階段は、これより最大で半分ほど長くなる。

なお `missing` は「2 つの道網のいちばん狭い隙間」ではない。道が相手からそれる方向に伸びていると、
実際に埋めるべき隙間より大きくも小さくもなりうる。

**7. 路面の質**

`長さ ÷ 所要時間` の加重平均で、**所要時間には登りも入る**。町の街路（誰も舗装できない）は
計算に入れない。1 マイルの土の道に石レンガが一区間あっても質はほとんど動かない — それが
正直な答えであり、舗装が身振りではなく仕事である理由でもある。

**8. 敷いたのに数えられていない所（不良点）**

規則を厳しくすると「置いたのに道にならない」が起きる。それを黙っているのが一番高くつくので、
`RoadNetwork.faults()` が 2 種類を返す:

| 種類 | 意味 |
| --- | --- |
| `headroom` | 道の材質を置いたのに、頭上 2 マスが空いていないので索引されていない |
| `step` | 索引済みの列どうしが隣り合っていて、高低差が 2〜3 ある（もう少しでつながる所） |

高低差 3 で打ち切るのは、それ以上は「壊れた道」ではなく「道と丘」だからである。

### 道の敷き方 — 4 百マスを 4 百回のクリックにしない

とぎれを許していたのは「良い道だから」ではなく「1 クリック 1 ブロックでは誰も敷かないから」
だった。クリックのほうを無くせば譲歩は要らない。

| 操作 | すること |
| --- | --- |
| **シャベルを持って右クリック長押し**（歩きながら） | カーソルのマスとその**周囲 8 マス**を道にし続ける。カーソルが飛んだぶんは**間を埋める**（振り向くたびに点線になっては道にならない） |
| **`R`** | 見ている所（**20 マス先まで**）から**足もとまで**を一気に道にする。坂は削り、窪みは橋で渡すので、崖に垂らした線ではなく索引が歩ける道になる |

どちらも草・土・砂・雪・**天然の砂利**を「踏み固めた土」に変える。花や草はどけ、
**張り出した葉は払う**（頭上 2 マスを空けるのは道普請そのものなので）。
**誰かが舗装した道（石畳など）はそのまま残す** — 踏み固めたら仕事を戻すことになるので。
同じ理由で `R` も見本ワールドも、**すでにある道をより悪い材質で上書きしない**。
素の石と、誰かが建てた庇の下は道にしない（前者は山とみわけがつかず、後者は頭上が塞がっている）。

掃き敷きは 2 マス以上の段差を越えない。索引が拒む段差を敷けてしまっては意味がないので、
そこは `R` で削る／埋めるのが正しい道具になる。敷いた列が索引に通らなかったときは
**その場でトーストが理由を言う**（「頭上が塞がっている」「段差が 2 マス以上」）。

### ゲーム速度（×1〜×16）

物流は**時間でできている**。路線をひき終えてから町が育つまでを実時間で待つのは、作った物を
見るための待ち時間であって遊びではないので、世界の時計を速くできるようにした。

**速くなるのは世界だけ**で、プレイヤーは常に等速のまま歩き、掘り、殴られる。

- **`dt` を掛けるのではなく、世界の 1 歩を N 回まわす。** `dt × 16` は当たり判定にも水の
  シミュレーションにも、書かれたときに想定していない数を渡すことになる。同じ `dt` を 16 回なら
  どの固定ステップの前提も壊れない
- 速くなるのは 水・時刻・モブ・落ちている物・作物・かまど・町と産業と輸送。
  **外に残してあるのは** 入力・プレイヤーの更新・採掘・画面・オートセーブ
- **被弾が 16 倍にはならない。** プレイヤーの無敵時間はプレイヤー側（等速）で減るので、
  受けるダメージは 0.5 秒に 1 回のまま。空腹も同じ理由で変わらない
- 1 フレームに世界へ使う時間には**上限（12ms）がある**。追いつけない機械では途中で切り上げ、
  画面には「早送り ×16（実効 ×9）」と**実際にできた数**を出す。嘘をつかないための行

### 見本ワールド

タイトル画面の**「見本ワールド（道と鉄道）」**は、固定シードの世界を**町と町を結ぶ 400 マスほどの
続いた道つき**で開き、プレイヤーをその上に立たせる。輸送の話は、1 本できあがった道の上に
立ってみるのがいちばん早い。道は普通の記録された edit として `runRoad` が敷くので、
**プレイヤーが敷いた道と 1 バイトも変わらない**（誰も歩かなくて済んだ、という点を除いて）。

**停留所と路線も最初から入っている。** 道だけ渡されても何も動かない世界なので、見本は
「動いているところ」を見せる責任がある — 両端に停留所が 1 つずつ立ち、それを呼ぶ路線が
1 本引いてある。予備の停留所と産業設置具も持ち物に入っているので、そこから広げられる。

**幅 3 マスで敷いてあるので、起動直後から荷車が走る。** 角度のついた区間は階段状になる
（道は上下左右にしかつながらないため）。

**そのうえで、線路が道の横に途中まで敷いてある。** 同じ 2 か所を、今度は曲線で —
道から 6 マス横に、**足もとの 48 マスだけ空けて**。線路敷設ツール、空けたぶんのレール
（＋予備）、そして**駅 2 つ**が最初から持ち物に入っている。**向こう側の端の駅はもう建って
いる**ので、プレイヤーがやることは「つなぐ」と「こちら側の端に駅を建てる」の 2 つである。

| | |
| --- | --- |
| なぜ空けるか | 完成した鉄道を渡されると**列車しか見えない**。道具も、途切れた所の紫の光の柱も、半分できた線がどう見えるかも見られない。手前を空けると 3 つとも目の前に出るうえ、埋める仕事は右クリック 2 回で終わる |
| なぜ向こうの駅は建っているか | 見本は**まるごと 1 つの物**を見せるためにある。両方無ければ「駅とは何か」を見ないまま建てることになるし、両方あれば駅は見えるだけで**建てる手が動かない**。片方だけ建っているのが、見て・作って・動くところまでが一度に通る唯一の形である |
| なぜ道の上ではなく横か | 道と線路は見本の 2 つの半分である。道の真上に甲板を渡すと片方が隠れるし、**高架は下から見上げるのが一番わかりやすい** |
| 起動直後に見えるもの | 道の横に**支柱の立った高架**、向こうの端に**屋根とホームのある駅**、手前の端に**紫の光の柱**（そこが敷き足す場所）、パネルに「列車: 線路が途切れている（南へ 10m）」 |
| つないだだけだと | 手前の端に**桃色の光の柱**が立ち、パネルが「列車: 線路の端に駅が無い」に変わる。ここが駅を建てる場所である |
| 駅まで建てると | 荷車 → **列車**。1 便 15 → 36。荷運びが町から駅まで木箱を運び、ホームで**貨車をつないだ列車**に持ち替わる |

**高さは地形をなぞらない。** 線路の甲板は、線に沿って測った地面（＋2 マス）の**包絡線**である
— どの測点から見ても、そこから許された勾配で下がっていった高さのうち一番高いもの。1 パスで
求まり、丘に埋まることがなく、窪みは**下りずに渡る**。これが「地形を追わない」の実装であり、
道との違いそのものでもある。

**許した勾配（0.15）を上限（0.2）のすぐ下に取ってあるのは、ゆるい線ほど高くなるからである。**
包絡線は丘からこの勾配で落ちていくので、勾配を半分にすると丘の影が 2 倍遠くまで届き、
半マイル先の山を避けるために線全体が持ち上がる。国じゅうを 30 マス上空で横断する見本は、
見せたいものを見せていない。

**それでも見本の線は谷を高く渡る。** 勾配を決めた鉄道が起伏のある土地を通れば、そうなるしか
ない — 掘って通ることができない以上、飛ぶしかないからである。**これは不具合ではなく、
道との違いそのものである**（道は 50% まで登れるし、削って通る）。手前の端が 20 マスほど
宙にあることもあるが、**敷設ツールは 48 マス先までなら宙の端にも狙いをつけられる**ので、
道の上に立ったまま端をクリックし、**空を見上げて 2 度目をクリック**すれば足せる。

見ただけでは分からない。そこで調査結果は真偽値ではなく**両端からどこまで届いたか**を返し、
4 か所に出す。

- **左のパネル** — 「未接続 / あと 128m」または「接続済み 384m / 石畳 / 荷車 / 荷 15」。
  到着側が求めている品を運んでいる路線には ✓ が付く。うまくいっていない理由はその下に並ぶ:
  「敷いたのに数えられていない: 段差 2 か所・頭上 1 か所」「道の高さが合っていない」
  「荷車: 幅が足りない（東へ 84m）」「遠回り ×1.34 — 運賃は直線距離ぶん」「登り 14 段」

### 全画面の地図（`M`）

右上のミニマップは 1 ドット 2 マスで 224 マス四方 — **町と町の間の半分にも届かない**。
輸送の話はその外側で起きるので、道がどこを通っているのか、どの 2 か所なら線路が引けるのか、
海岸をどれだけ回り込んでいるのかは、歩いていくまで見られなかった。

**`M` で同じ地図を画面いっぱいに開く。** ＋ / − とマウスホイールで **1 ドット 1 マス〜16 マス**
（一辺 512〜8192 マス）。1 ドット 1 マスなら町の建物が数えられ、16 マスなら 4000 マス四方が
一度に入る。

| | |
| --- | --- |
| 実装 | **ミニマップと同じクラスに違う数字を渡しているだけ**。地形の色も道の色も重ね方も 1 か所にしかないので、隅の地図とここで意味が食い違うことがない |
| 動かせる | **ドラッグで動く。** 長いあいだ「戻り方が要るし、今どこにいるかを見失える地図にはしたくない」という理由で断っていたが、それは正しい心配の間違った答え方だった — 2 つの町が同時に入る縮尺まで引くと、その 2 つはどちらも中心から遠い所に来る。動かせない地図は「読むために歩く」地図になる |
| 戻り方 | 3 つある。中心が自分から外れた瞬間に**バーの「自分の位置へ」が光る**、`Home` でも戻る、そして**地図を閉じて開き直すと必ず自分の位置に戻る**。プレイヤーの矢印は**実際にいる場所**に描かれ、画面から外れたら描かれない（縁に矢印を貼ると、光っているボタンと同じことを二度言うことになる） |
| 場所を選ぶ | **クリックするとその場所が選べる。** 座標が下のバーに出て、桃色の印が地図に残る（町や荷と同じ「印」の仕組み）。カーソル位置ではなくクリックにしてあるのは、ボタンを押しに行くとポインタが地図から出てしまうからである |
| ワープ | 選んだ場所へ飛べるが、**デバッグモードが入のときだけ**（`C` の全アイテムと同じ扱い）。地図で見つけた所まで歩くのがこの遊びの大半なので、そこを飛ばせるようにはしていない。`G` の座標ワープはこれまでどおり無条件で使える — 知っている座標を打つのと、場所を指すのは別のことである |
| 見える範囲 | **探索済みの所だけ**。一度読み込まれたチャンクは地表だけ控えてあり、遠く離れても・読み込みが外れても地図には残る。行ったことがない所は暗いままで、推測では描かない（ミニマップも同じ） |
| 描き直し | どの縮尺でも**4 フレームで 1 周**（毎フレーム 1/4 ずつ）。大きい地図が小さい地図よりフレームを食うことはない |

**地図に残るのは「見た所」だけである。** チャンクは読み込まれたときと捨てられるときに
**地表だけ**控えられる（列ごとに「一番上のブロックの高さ・その id・そこの水量」の 3 つ、
`src/game/cartography.ts`）。地図はまず読み込み中の世界を見て、無ければこの控えを見て、
それも無ければ**何も描かない**。だから

- 歩いてきた海岸線は、遠く離れて読み込みが外れても地図に残る
- 行ったことのない谷は、隣まで来ていても暗いまま — 地形はシードから引けるが、**引かない**。
  「見ていない所」を描く地図は、どこまで歩いたかを答えられなくなる
- 控えはセーブに乗る（チャンクごとに 4 面 — 高さ・ブロック id の下位と上位・水量 — を
  ランレングス圧縮と生バイトの短いほうで符号化して約 670 バイト）。localStorage が溢れた
  ときは**控えだけを落として**ワールドは保存する — 歩けば戻ってくるのは、この地図だけ
  だからである

### 道しるべ（世界に光の線で描く）

道は「見た目」ではなく**索引**で判定するので、立って眺めても接続状態は分からない。パネルは可否を、ミニマップはおおよその場所を答えるが、プレイヤーが実際に訊きたいのは
**「どこを敷けばいいのか」**で、それに答えられるのは世界の中だけなので、地面に直接描く。

| 描く物 | 意味 |
| --- | --- |
| **緑の線** | 荷を運んでいる道。実際に索引されている道筋をなぞる |
| **橙の破線＋両端の光の柱** | まだ足りない区間と、**道が途切れている 2 点** |
| **淡い水色のタイル** | 索引が「道」と数えている列。プレイヤーの周囲 40 ブロックだけ |
| **赤い光の柱** | 敷いたのに数えられていない所（頭上が塞がっている／段差が急） |
| **琥珀色の光の柱** | 荷車には幅が足りなくなる所 |
| **緑の光の柱** | 荷運びの現在地（見えていない遠くの荷も柱は立つ） |
| **紫の光の柱** | 敷きかけの線路が途切れている所 |
| **桃色の光の柱** | 線路の端が町まで来ているのに駅が無い所 |
| **黄色の光の柱** | **列車が信号待ちで詰まっている所。** 向かい合った 2 本ぶん、両方に立つ |
| **水色の線と光の柱** | **停留所・駅と、それが接続判定になっている町や産業を結ぶ**（下） |
| **灰色の光の柱** | 何にも接続していない停留所・駅（置いてはあるが、荷は 1 個も通らない） |

#### 接続の線 — どこにつながっている停留所なのか

停留所がどの町を担当するかは**置いた瞬間に記録されて二度と変わらず**、どの産業から積むかは
**そのつど近さで決まる**。この 2 つは地面を見ても分からないのに、荷が動くかどうかを決めている。
そこで、**プレイヤーの周囲 110 マスの停留所と駅から、接続先へ水色の線を引く**。線の向こう端
（町の集荷所の戸口、産業の小屋）にも短い光の柱が立つので、「この停留所はあの町のものだ」が
一目で分かる。何にもつながっていない停留所は灰色の柱だけになる — 建設途中として正しい状態
なので、赤（＝敷いたのに数えられていない）とは分けてある。

**置く前にも同じ線が出る。** 停留所を持って地面を狙うと、そこに置いた場合の接続先へ
**破線**が伸び、画面には「ここに置くと 陽の灯り（町）につながる」と出る。どこにも届かない
場所なら「ここに置いても何にもつながらない（一番近い町まで 96m / 72m）」と、**あと何マス
足りないか**が出る。駅も同じで、線路の端を狙うと「この端に駅を建てると 川の羊毛 に届く（31m）」
と出る。停留所どうしが近すぎて置けない場合もその場で言う。

淡いタイルがいちばん地味で、いちばん正直な表示になっている: 砂に埋もれた道は索引から外れるので、
**「敷いたのにつながらない」がその場で見える**。

線は地面に沿わせて置く（1 ブロックずつ地表の高さを拾い直す）。まだ道のない区間を 2 点間の直線で
引くと、途中の丘に埋まって、いちばん見せたい所でいちばん見えなくなるため。

設定の「道しるべ」で消せる。線の形が変わったときだけジオメトリを作り直し、光の柱は使い回すので、
何も起きていない世界では毎フレームの費用がほぼない。

### 集荷所 — 輸送は建物どうしで行う

町は座標ではなく建物の集まりなので、区間の両端も**建物**にした。町ごとに 1 棟が**集荷所**で、
荷はその**戸口から出て、相手の集荷所の戸口に入る**。停留所はその町のどこに置いてもよく、
荷の出入りはいつも集荷所の戸口である — 停留所は「この町を路線が呼ぶ」という宣言であって、
荷役場ではない。

- **選び方** — 建物を見ると画面中央に名前と役割が出る（「川の羊毛の鍛冶屋 — 住居」）。
  そこで **F** を押すと、その建物がその町の集荷所になる
- **既定** — 町の中心にいちばん近い建物。町の街路が最初から戸口まで届いているので、
  建物のことを何も考えなくても道はつながる
- **選ぶ意味** — **戸口から通りまでの歩きも道のりに入る**。奥まった建物を選べば 1 便の時間が
  延び、道端の建物を選べば縮む。上の検証シードでは、集荷所を町外れの鍛冶屋に移した瞬間に
  路線が 21m から 60m になった
- **表示** — パネルは「鍛冶屋 → 書庫 · 荷運び 1 · 東へ 43m」、台帳は「川の羊毛・鍛冶屋 ⇄
  川の羊毛の分かれ・書庫」、世界では両方の戸口に短い光の柱が立つ

建物そのものも「名前のある物」である。職業から名前が付き（鍛冶屋・書庫・農家・肉屋・商店）、
同じ職業が 2 軒あれば番号が付く。戸口の位置は**戸口を開けた側**が記録するので、
位置がずれようがない。

**新しい建物には道が自動で付く。** どの家も戸口から通りへ向けて 4 マスまでの短い道を敷く
（隣の区画に当たったらそこで止まる）。生成される町も、発展で増える建物も、分村も同じ。
「戸口が草の上に開いている」のが、建物を輸送の端にできない一番よくある理由だった。

### 荷運び — 詰まらない、ワープしない

輸送の真実は**抽象的な時計**のほうで、荷運びはその見た目でしかない。プレイヤーが 64 ブロック
以内にいれば実体化して実際に道を歩き、離れれば実体は消える。どちらの場合も進捗を決めるのは
時計のほうで、荷運びは**追いかけるだけ**。

以前は逆で、見えている荷運びが進捗を決めていた。そのため入口の角に引っかかった荷運びが
路線ごと止め、しかも**見ている間だけ止まる**という最悪の壊れ方をしていた。道を掘り返された
ときは、輸送中の荷は積み地の在庫に戻る。

それを直したあと残っていたのが**ワープ**である。原因は 4 つあり、4 つとも潰した:

1. **登れない道**（本命）— 索引が高低差 2 を許し、荷運びの跳躍は 1.11 マスしか上がらなかった。
   規則を 1 に直した（上の「2.」）
2. **陸上に段差踏み越えが無かった** — `stepUpMove` は水中でしか呼ばれず、陸では毎回**弾道
   ジャンプ**していた。跳べば 0.4 秒の硬直が要り、角では失敗する。経路を追う Mob
   （荷運び・荷車）は陸でも踏み越える。**踏み越えに成功したらジャンプはしない**
   （両方やると、縁石に上がった直後に自分から飛び出す）
3. **殴られると 5 秒逃げた** — 逃走判定が `follow` より手前にあったので、一発殴れば必ず
   紐が切れた。荷を持った者は逃げない
4. **ワープそのもの** — 遅れたら座標を書き換えていた。今は**ゴムひも**にした:
   遅れるほど速く走る（最大 3 倍）。24 ブロック（`PORTER_LOST`）以上離れて初めて諦め、
   そのときも**移動させずに消す**。次のフレームが荷の位置に新しい 1 体を描く。
   24 ブロック離れていれば両方を同時に見てはいないので、瞬間移動としては見えない

ブラウザ通しでは、見えている荷運びを 8 秒間 100ms ごとに採って
**1 フレームの最大移動が 0.39 ブロック**であることを毎回確かめている。

接続しているのに荷が動かないときの理由はたいてい**在庫がまだ 1 便分たまっていない**ことなので、
パネルはそれも言う（「荷運び 0 · 出荷待ち 在庫 3/6」／「荷運び 1 · 東へ 43m」）。

### チュートリアルの次の目標

チュートリアルが終わると目標一覧に移る。最初は「一次産業を建てる」— 町はどこも原料待ちで
止まっているので、次にやることは必ずそれである。そのあとが「路線をもう 1 本ひらく」で、
これは以前は**「つながっている輸送路 1 / 2」としか言わず、どこを結ぶのかも、どこまで届いて
いるのかも一切示さなかった**。目標が指す区間は、チュートリアル中と同じ扱いにした:

- 未接続の区間があれば、**その 2 つの停留所を名指しし**、「あと 368m・道 19 個ぶん」と
  作業量で言う。コンパスの `⋯` とパネルの行と世界の橙の破線・光の柱が、すべてその区間を指す
- 路線がまだ 1 本しかなければ、「[N] で新しい路線をひく」と言う — この段階で足りていない
  のは道ではなく**路線**なので、シャベルを指すのは間違いである

目標は全部で 11 個あり、産業を建てる・工場に原料を届ける・**原料が 2 種類要る工場を動かす**の
3 つが、この遊びの新しい骨格をなぞる形で並んでいる。

### 町の発展

町は 4 段階（集落 → 村 → 大きな村 → 町 → 都市）育つ。必要な発展度は段階ごとに上がり
（8 / 16 / 26 / 40）、段階が上がるたびに区画が埋まり、生産が速くなり、欲しがる物が増え、
村人の取引表が広がる。**どの区画がどの段階で建つかは決まっている** — 真ん中から外へ、
広場と商店が先、住宅と工場が後。だから半分育った町も、ちゃんと町の形をしている。

発展で建つ建物も**用途で見た目が変わる**。商店は街路に面した壁がまるごと硝子で日よけが付き、
工場は丸石と石レンガの角、高い窓の帯、そして煙突 2 本で、町で一番背が高い。住宅は町で唯一の
切妻屋根である。

発展した町の建物は、ワールド生成に手を入れるのではなく**普通の「記録される編集」として書く**。
`World.edits` は唯一の永続ブロック置き場で、チャンクを読み込むたびに `World.addChunk` が
必ず適用し直すので、これだけで建物はチャンクの出入りに耐える。書き込みは冪等なので、
留守のあいだに発展した町は、戻ってきたときに自分で建つ。

上書きしてよいのは空気と天然の地面（草・土・砂・雪・花・葉・水、それに耕地と作物）だけに限っている。
プレイヤーが置いたチェストも壁も、町の元の建物も触らない。失敗の仕方は「新しい建物に穴が空く」で、
「作った物が消える」にはならない。耕地と作物が入っているのは、町が前の段階で作った畑の上に
次の段階の家が建つことがあるからで、ここを避けていると**床が抜けた家**が建っていた。

### 集荷所から道までの数マス

町の街路は**生成されるブロック**で、道の索引（＝プレイヤーが敷いた列）には入らない。
そのため集荷所の戸口は基本的に「道の上」にはなく、**毎回の運搬の最後の数マスは町の中を歩く**。

これを以前は**戸口から街路までの直線**で描いていた。荷運びは荷の現在地に向かってまっすぐ歩くので、
荷が家の中に入った瞬間、荷運びは壁にぶつかって止まる。しかも街路の点は町の格子の縁なので、
相手の方角によっては**町を端から端まで**横切ることになり、その直線は町じゅうの建物を貫く。

いまは 3 段階で決める。**①** 誰かが戸口から道まで舗装していれば索引がそれを歩く。
**②** なければ**建物の区画を避けて回り込む**（4 近傍・平面・区画データだけで解くのでチャンクの
読み込み状態に依らない）。**③** それも無理なら従来どおり直線。

避けるのは**建物だけ**。井戸や街灯や木は 1 ブロックなので、段差登りとジャンプで越える。

回り込みの探索距離は**町の対角ぶん**まで許してある（`AROUND_LIMIT`）。街路の格子は 60 ほど
あるので、対角の戸口から反対の角に道が来ているとき、4 近傍では 120 歩を超える。そこで打ち切ると
**②** が静かに失敗して **③** の直線に落ち、それは町の真ん中を貫く線である — この関数がある
理由そのものになってしまう。

### 区画を均す

家を建てる前に、その区画の地面を床の高さまで均す（足りなければ最大 8 マス埋め、
高すぎれば 5 マスまで削る）。壁の 1 マス外まで均すので、戸口の前が崖にならない。

これがないと**家が浮く**。町の台地が完全に平らなのは内側だけで、そこから外側 14 マスかけて
元の地形に戻る。発展した町が建てる**外側の区画はちょうどその帯に入る**ので、
台地の高さのまま床を置くと、下り側は空中に浮く（実測で最大 3 マス）。

分村は最初からこれをやっている（誰も均していない地形に建てるので）。発展した町の建物も同じ理由で
同じ扱いが要る、というだけの話だった。

均す処理は**列ごと**に走るので、区画が 2 チャンクにまたがっても各チャンクが自分の分を均す。
埋めるのも削るのも `place` を通すので、道の防御もプレイヤーの物を触らない規則もそのまま効く。

そのぶん、**書き込む前に計画を「1 セルにつき最後の 1 ブロック」へ畳んでおく**必要がある。
建物の計画は大工の手順どおり（壁を建ててから戸口と窓を開ける）に並んでいるので、素直に順番に
書くと、戸口の「空気」が自分で建てたばかりの壁に阻まれて拒否される。畳んでおけば各セルは
一度だけ、大工が最後に決めた物で書かれる。

### 建物の床の高さ

家の床は**外の地面と同じ高さ**に置く。町の台地は `baseY` が「最上段の地面ブロック」なので、
床の高さはその 1 つ上 — `buildHouse` に渡すのは `baseY + 1` になる。1 つ低く置くと戸口の
2 マスのうち下の 1 マスが地面に埋まり、外から見ると**高さ 1 マスの穴**になって通れない。

分村の `planOutpost` だけは `baseY` がもともと「最初の空気の高さ」なので、そのまま渡す
（自分で地面を均すため、台地とは基準が違う）。分村の道も同じ理由で `baseY - 1`、つまり
均した地面そのものに敷く。

なお、この修正より前に**発展して家が建っていたワールド**は、古い高さの壁が編集として残るので
新しい家と重なる（新しい家は 1 つ上に建つ）。上書き白リストが石レンガや木材を弾く以上、
自動では直せない。作り直すのが早い。

### チュートリアルの分村

**生成される町同士を隣に置くことはできない。** 町はシードから決まる 320 ブロック間隔の格子に
乗っていて、それぞれ街路の格子が乗るだけの台地を持つので、数十ブロック離れた 2 つの町は互いの上に
立つことになる。だからチュートリアルの最初の運搬は 400 ブロックの徒歩で、その次に教わる
「道を敷く」はシャベルで午後いっぱいの作業だった。どちらも**チュートリアルではなく本編**である。

そこで、チュートリアルには専用の相手役を用意した（`src/game/outpost.ts` と
`village.ts` の `planOutpost`）。**最初に見つけた町だけ**が、少し先に**分村**を持つ。家 2 軒
だけの小さな集落で、そこが最初の納品先になり、最初の路線の相手になる。以降の町同士は今まで通り
数百ブロック離れていて、そこが本編。

分村は**世界で唯一、何も無いところから物を作る場所**でもある。町はどこも原料が届くまで動かない
ので、それだけの世界ではチュートリアルに「最初の 1 個」がない。

| | |
| --- | --- |
| 距離 | **書かずに導く**: 町の台地の半径（56）＋ 分村の半径（16）＝ 72 が下限で、76 を狙う。これより近いと分村の平地が町の台地の中に入り、高さの違う 2 枚の平地が重なる |
| 地面 | 自分で均す。半径 12 の円を、覆っている**一番高い地面**に合わせて埋め立てる |
| 埋め立ての上限 | 7 ブロック。これを超える起伏の場所は候補から外す |
| 建て方 | 村の発展と同じ**記録される編集**。ワールド生成も worker も一切変わらない |
| 見つからない場合 | 何もしない。チュートリアルは従来通り一番近い本物の村を指す |

地面を「削らず埋める」のは、書き込みが土・砂・草・葉・水・空気しか置き換えないから。丘は削れない
（プレイヤーの建築を守るための制限がそのまま効く）ので、**一番高い地面に合わせて低い側を埋める**。
結果は村の台地と同じ、段のついた平地になる。

分村はシードから導き直せない唯一の村なので、**町の中で唯一、位置と名前もセーブに乗る**
（`SavedVillage` の任意フィールド）。

**道の踏査から見ると、分村は「町」ではなく「場所」である。** 町には生成された街路の格子があり、
道はそこに触れれば到着したことになる。分村にあるのはただの平地なので、街路の格子を持たせると
**建っていない街路**で踏査が終わってしまう — 丘の斜面のどこかで、しかも分村自身の高さで、
つまり空中に描かれた道になる。だから `townPlace` は分村に `town: null` を返し、平地の**縁**
（`OUTPOST_PAD` = 12）に道が届いたら到着とする。縁であって中心でないのは、中心には家が建って
いるからである。

## 割り切っていること

- 溶岩・レッドストーン・ネザーはない。
- 苗木がないので、木を切ってもその場所に木は生えてこない。
- 分村を持つのは最初に見つけた村だけ。既存のセーブでチュートリアルを先に進めてしまっている場合は
  分村は建たない（進行中のチュートリアルを書き換えないため）。
- 水車による動力はない。
- **川と天候はない。** 世界にある水は海と、プレイヤーが引いた水路・貯水池だけである。季節も
  雨も水位の上下もないので、水は置いた場所から動かない限りそこにある。
- 生成された水はプレイヤーが手を入れるまでシミュレーションに乗らない。海を掘れば、その周りの
  水だけが目を覚まして穴を満たし、また眠る。
- 生産の連鎖は 2 段だけ。産業 → 町の工場 → 消費で終わりで、加工品をさらに組み合わせる町はない。
- **一次産業は 1 か所につき 1 種類しか掘らない。** 石炭と鉄が同じ丘に埋まっていても、建てられる
  のはどちらか一方で、もう一方は 40 マス離れた別の場所から掘ることになる。
- **産業は資源を減らさない。** 掘り出す速さは建てた日の資源の多さで決まったきり変わらないので、
  「もっと掘れる場所へ移す」という遊びは無い。作った網が値打ちを失わないほうを取った。
- **露頭は生成される地形の一部で、プレイヤーが作れるものではない。** 石炭や鉄のブロックを自分で
  積んでも産業の判定には通る（判定はブロックを数えているだけ）が、それは資源を運ぶより高くつく。
- **町の中の状態は保存しない。** 建物の食料庫の中身、通勤している人、駅で待っている人は
  セーブに乗らない。人数は用途と村の段階から導き直し、残りはまた埋まる。開き直した町は
  少しお腹が空いているだけである。**村の在庫と発展度はこれまでどおり保存される。**
- **建物単位なのは「入ってくるほう」だけである。** 建物はそれぞれ固有の在庫・需要・人口を持ち、
  集荷所は近い建物から順に配る。けれど**町が出荷する物はこれまでどおり町ひとつの山**で、
  「この工場が作った 3 個」と「あの倉庫にある 5 個」は区別されない。工場は町を代表して
  加工しているのであって、自分の在庫を持っているわけではない。
- **車両は買わないし、選べない。** 路線に走らせるものは、区間ごとに「実際に何がつないでいるか」
  だけで決まる。道を敷いてから改めて「荷車」を選ばせるのは同じ質問を 2 回することなので、
  買い物としての車両は入れていない。台数も選べない（長さで決まる）。
- **ダイヤも運賃設定も赤字もない。** 路線は引くか引かないかで、走らせる本数も時刻も収支も無い。
  お金は届いたときに入るだけで、出ていくことはない。
- **停留所は名前を付け替えられない。** 置いた場所の町か産業から自動で付く。
- **町は勝手に育たない。** 人が通おうが商店が繁盛しようが、発展度が入るのはプレイヤーが
  荷を届けたときだけである。人が生むのは需要であって、成長ではない。
- **通勤する村人は保存されない。** プレイヤーが離れると消え、戻ると湧き直す（荷運びと同じ）。
  話しかけて取引はできるが、その村人が明日も同じ所にいるとは限らない。
- **人は「品目」であって乗り物ではない。** 駅で待っている人が列車に乗り込む様子は無いし、
  客車の中に人が座っているわけでもない。荷が無い便に人数が乗るだけである。
- **町の中の通勤は、道の質も距離も見ていない。** どの建物からどの建物へ歩いても同じ時間が
  かかる。村の通りは短いので、測っても得られるものが無かった。
- ゲーム速度を上げてもプレイヤーは速くならない。世界が先へ行くだけで、早送りしながら
  自分が 16 倍で走ることはできない。
- 道はとぎれてはいけない。1 マス抜けたらそこで路線は切れる。20 マスまでのとぎれを許していた
  時期があるが、「つながっている」が見た目と一致しなくなるほうが高くついた。代わりに敷く手間の
  ほうを無くしてある（長押しの掃き敷きと `R`）。
- 町は衰退しない。輸送が止まっても、育った町がそれで縮むことはない。
- **車庫もダイヤも番線もない。** 線路に置けるのは駅と信号機だけで、駅にできるのは
  「ここで積み下ろしする」と言うことだけである。停車時間という概念も無い。
- **駅は編成を待たせない。** ホームに積まれている木箱はその村の在庫を映しているだけで、
  荷が駅に溜まってから列車が出る、という順番にはなっていない。時計はひとつのままで、
  荷運びと列車の持ち替えが起きるだけである（見ている人の前でだけ線が止まるのを避けるため）。
- **列車の当たり判定も「上に乗れる面」だけである。** 壁も柱も見た目なので、客車の側面は
  すり抜けられる。戸口を狙わなくても入れる代わりに、車内で壁に押し出されることもない。
- **列車に乗れるのはプレイヤーだけである。** 村人も荷運びも列車には乗らないし、落ちている
  物は車両を素通りして下へ落ちる。
- **全画面の地図はドラッグで動かせる**（以前は動かせなかった）。**見えるのは探索済みの範囲だけ**で、
  行ったことがない所は暗いまま — 記録してあるのは地表 1 段だけなので、洞窟も建物の中も
  地図には出ない。動かした先も同じで、**歩いていない所はいくら引いても暗いままである。**
- **地図から飛べるのはデバッグモードのときだけ。** 場所を選んで座標を見るのはいつでもできるが、
  そこへワープするのはデバッグモードが入のときだけである。
- **地図の印は保存されない。** クリックで置いた印は地図を閉じると消える。目的地に旗を立てて
  おく仕組みではない。
- **当たり判定は甲板だけである。** 上は歩けるが、**支柱には当たり判定が無い**（見た目である）。
  横から高架の腹にぶつかることもなく、足もとから 0.35 マスより高い甲板は歩いては乗れない
  （跳べば乗れる）。
- **甲板を踏めるのはプレイヤーと列車だけである。** 荷運び・荷車・そのほかのモブと落ちている物は
  掃引しか見ていないので、高架の上に落とした物は下へ落ち、モブは高架を素通りする。
- **1 つの節点に枝は 1 本まで。** 分岐は作れるが、作れるのは Y 字までで、両渡り（ダブルスリップ）
  は無い。枝を出せる向きも本線から 31° までで、それより振れた向きは分岐ではなく別の線路が
  横切っているだけなので断られる。
- **線路には緩和曲線もカントも無い。** 2 つの円弧の継ぎ目で曲率が飛ぶ。
  枕木の間隔は**水平**弧長で等間隔なので、勾配の上限（20%）では真の長さより 2% 詰まる。
- **詰まったら自動では解かない。** 単線で列車が向かい合うと本当に止まる。黄色い灯と光の柱と
  パネルの一行で、どこで詰まっているかは言うが、待避線を作るのも信号を抜くのもプレイヤーの
  仕事である。どちらを待たせるかを決める仕組み（追い越し・待避の自動運用）は無い。
- **信号の自動配置も、分岐の自動制御も無い。** どこを閉塞に切るかは全部手で決める。
- 荷車の当たり判定は 1.4 マス四方の正方形で、長さを持たない。「幅 3 マスでないと通れない」は
  当たり判定ではなく**網の規則**で、見た目のほうがそれに合わせてある。
- **「レール」ブロックは無くなった。** 鉄道は曲線のほうに一本化してあり、路面としてのレールも、
  それを置く操作も、それが道の索引に乗る仕組みも消してある。**レールという持ち物は残っている**
  — 線路敷設ツールが 1 マスにつき 0.5 本食べる材料がそれである。**古いワールドに残っている
  レール列は砂利に変わる**（セーブ形式は変えていない）。レールで橋や道を作ってあった所に
  穴が開かないようにするためで、その道は砂利の道として索引に残る。
- **今回から、2 マスの段差や木の下を通っていた道は切れる。** 既存のワールドはそのまま開くが
  （セーブ形式は変えていない）、そういう道を使っていた路線は未接続になる。どこで切れたかは
  赤い光の柱とパネルが指すので、直せば元に戻る。
- **斜めだけでつながっていた道も切れる。** シャベルの掃き敷き（3×3）で作った道は元から
  上下左右でつながっているので影響を受けない。切れるのは `R` や見本ワールドが敷いた
  **幅 1 の斜め道**で、これらは今後は階段状に敷かれる。
- 価格は需要で動かない。求められている品は発展度と運賃が増えるだけで、相場という概念はない。
- マルチプレイヤーはない。
- 音はない。

## 確認用の固定シード

地形生成をいじった時に「なんとなく違う世界になった」で済ませないために、確認はいつも同じ
ワールドで行う。シードは `voxelcraft`（数値では 2061350291）で、`src/game/seeds.ts` に定数として
置いてある。

- タイトル画面の**「検証用ワールド」**ボタンで一発で開く。
- URL に `?seed=...` を付けると、タイトルを経由せずそのシードのワールドが立ち上がる
  （例: `http://localhost:5173/?seed=voxelcraft`）。スクリーンショットや不具合報告をリンクで
  共有できる。
- ポーズ画面と `F3` に現在のシードが出る。ポーズ画面のシードはクリックでコピーできる。
- `src/test/seeds.test.ts` がこのシードのランドマークを固定している。スポーンが (0, 53, 0) で
  あること、取引できる町が平坦な台地の上にあること。
  地形生成を変えるとこのテストが落ちるので、変更が意図的かどうかを必ず判断することになる。

## アーキテクチャ

描画に依存する層としない層を分けてある。`src/world` と `src/game` は three.js を import しないので、
Vitest から Node 上でそのままテストできる。

```
src/
  core/       ノイズ・PRNG・AABB 衝突といった土台
  world/      ブロック定義、チャンク、地形生成、光、水シミュレーション、レイキャスト、ティック
  game/       プレイヤー、持ち物、クラフト、精錬、採掘、戦闘、満腹度、モブ、交易、セーブ
              町の工場と需要（villages）、町の建物・人口・通勤（townEconomy）、
              一次産業と資源の判定（industry）、停留所と路線（lines）、
              停留所に何が付いているか（sites）、
              道と路面（roads）、道を敷く（paving）、
              自由曲線の線路（tracks）、路線の区間を走らせる（transport）、
              チュートリアルと目標（questline）
  render/     テクスチャ生成、メッシャ、チャンク描画、空、エンティティ、エフェクト、
              自由曲線の線路の描画（trackRenderer）
  workers/    地形生成ワーカーとそのプール
  ui/         HUD・コンテナ画面・メニュー・入力（DOM オーバーレイ）
  test/       Vitest
```

地形生成は Web Worker のプールで並列に行い、メッシュ生成と光の伝播はメインスレッドで
フレームあたりの予算を決めて少しずつ進める。こうすることで隣接チャンクのデータを
スレッド間でやり取りせずに済み、ロード中もフレームが落ちにくい。

## 開発

```bash
npm run typecheck   # tsc --noEmit
npm run lint        # ESLint
npm test            # Vitest（描画に依存しないロジック）
npm run build       # 本番ビルド
npm run smoke          # Playwright で実際にブラウザを動かしてスクリーンショットを撮る（約 8 分）
npm run smoke:economy  # そのうち経済まわりだけ（約 2 分）
```

**確認はどこでするか。** 描画に依存しない層はすべて Vitest で見る（653 件・3 秒）ので、
ブラウザを立ち上げる理由は 3 つしかない — `game.ts` の配線、DOM、そして実際に絵が出るか。
だから遅い確認は最後の砦であって、日常の確認ではない。

| | 何を見るか | 時間 |
| --- | --- | --- |
| `npm test` | `src/world` と `src/game`（three.js に触らない層）ぜんぶ | 3 秒 |
| `npm run smoke:economy` | 起動 → 村 → チュートリアル → 停留所と路線 → 道 → 一次産業 | 約 2 分 |
| `npm run smoke` | 上に加えて 荷車・鉄道・信号・地図・農業・水・戦闘・セーブ | 約 8 分 |

`npm run smoke` は起動中の dev サーバに対して実行する。タイトル画面 → ワールド生成 →
採掘 → レシピ一覧でのクラフト → 夜と戦闘 → 村と交易 →
**停留所を置いて路線をひく・道の接続判定・舗装による路面の改善・交易台帳・運賃・荷運び・町の発展** →
**敷設ツールで曲線を敷き、既存の端につなぎ、断られる形を確かめ、谷に支柱を立てる** → 農業 → 洞窟と松明 → **掘った池から水道橋を引いて水門で操る** →
ポンプで汲み上げる → 潜って溺れかける → 死亡とリスポーン → セーブしてリロード → URL のシード指定、
までを通しで動かし、`screenshots/` に画像を書き出す。ワールドは固定シードなので地形は毎回同じだが、
村人の職業や、探索して見つかる洞窟の位置は実行ごとに振り直されるので、ログの数値は完全には
一致しない。

**待ち方**: 各手順は固定時間の `sleep` ではなく、**次に主張したいことそのもの**を待つ
（水が向こう端に届く / 取引が成立する / 区間が調査される）。ソフトウェア描画ではゲームが実時間の
数分の一で進むため、「たぶん足りるはずの秒数」は遅いマシンでは足りず、速いマシンでは無駄になる。
`until()` はタイムアウトで**失敗する**（黙って先に進まない）ので、待ちがそのまま検査になっている。
経過時間は各行の先頭に `[123.4s +5.6]` 形式で出るので、どの手順が重いかはログを見れば分かる。

**世界の時計は待たずに回す。** この確認が待っているものの多くは世界の時計である — 道が調べ直される
（2 秒ごと）、荷運びが 100m 歩く、工場が加工する、産業が掘る。実時間で座って待つと 10 分の大半が
それで消えるが、**誰かが座っていようがいまいが同じ秒数が同じように進む**。そこで `advance()` は
`voxelcraft.fastForward(秒)` で時計を手で回し、条件が満たされたところで止まる。中身はゲーム速度と
まったく同じ（`stepWorld` の繰り返し）で、フレーム予算が無いだけである。

**回せないもの**: チャンク生成は worker の仕事なので早送りできない。世界が**存在する**のを待つ所は
今までどおり `settled()` で待つ。実際、残っている時間のほとんどはこれと、実時間でしか確かめようの
ない手順（列車に乗る・荷運びが跳ねないことを 8 秒サンプリングする・シャベルで 4 秒歩く）である。

```bash
npm run dev &
npm run smoke -- http://localhost:5173/ screenshots
```

### GitHub Pages への公開

`main` に push すると `.github/workflows/pages.yml` が typecheck・lint・テスト・ビルドを通し、
`dist/` をそのまま Pages へ上げる（壊れたビルドで動いているサイトを置き換えないため、
CI と同じ検査を先に通す）。公開先は **https://kamocyc.github.io/claude-web-test-24/**。

- リポジトリ設定をいじる必要はない。ワークフローの `configure-pages` が
  `enablement: true` で Pages のソースを「GitHub Actions」に切り替える。
- `base: './'`（`vite.config.ts`）なので、出力は**サブパスでもドメイン直下でも動く**。
  リポジトリ名を設定に書かないので、名前を変えても壊れない。
- ワーカー・テクスチャ・セーブはすべてブラウザ内で完結しており、サーバ側の処理は無い。
  静的ファイルを置くだけで動く。
- Actions タブから手動実行（`workflow_dispatch`）もできる。ただし手動実行のボタンは
  **デフォルトブランチにこのファイルが入ってから**現れる、という GitHub の仕様に注意。

### デバッグ: 全アイテム無限

線路や道を試すのに材料を集めるのは、試したいこととは関係のない待ち時間である。
ポーズ画面（`Esc`）の**「デバッグ: 全アイテム無限（C で一覧）」**を入にすると、

- **`C`** で**ゲーム内の全アイテムが並んだ棚**が開く。取り出しても減らず、そこへ戻すと捨てられる
- **持ち物が減らなくなる。** ブロックの設置も、道の掃き敷きも、線路の敷設も、食事も、
  クラフトの材料も、交易の支払いも消費されない

**入っていることは画面に出る**（緑のバッジと `F3`）。何でも無料になるモードが黙って入っている
ワールドは、「ルールが効かなくなった世界」と見分けがつかないので。

**仕掛けは持ち物のフラグ 1 つ**である。何かを支払う道はすべて `Inventory` の `remove` /
`consumeAt` / `has` を通るので、プレイヤーの持ち物に `unlimited` を立てるだけで、
呼ぶ側は 1 か所も「デバッグモードがある」ことを知らずに済む。

**`count` だけは正直なままにしてある。** これはレシピ一覧・交易画面・チュートリアルの
「羊毛を 5 個納品」が読んでいる数で、ここが無限を返すと**何も持っていないのに納品が成立する**。
このモードが約束するのは「減らない」ことであって、「持っていないものを持っていることにする」
ことではない。

設定はワールドのセーブではなく**環境設定**（`localStorage`）に置いてある。モードの入切で
ワールドの中身が黙って変わることがないように。

### デバッグ用コンソール API

ゲーム中はブラウザのコンソールから `voxelcraft` が使える。

```js
voxelcraft.give('diamond_pickaxe')   // アイテムを配る
voxelcraft.setTime(0.7)              // 0=日の出 0.25=正午 0.5=日没 0.75=真夜中
voxelcraft.gotoVillage()             // 一番近い村へ飛ぶ
voxelcraft.waterDepth(x, y, z)       // その柱の水深（ブロック）
voxelcraft.waterSurface(x, z)        // その柱の水面の高さ（小数、乾いていれば null）
voxelcraft.pourWater(x, y, z, 3)     // 3 ブロック分の水を注ぐ
voxelcraft.difficulty()              // 今の難易度と、その効果の中身
voxelcraft.setDifficulty('peaceful') // 難易度を変える（ポーズ画面と同じ扱い）
voxelcraft.hostiles()                // 今いる敵の数
voxelcraft.findCave()                // 近くの洞窟へ潜る
voxelcraft.spawnMob('zombie')        // 目の前にモブを出す
voxelcraft.toggleFly()               // 飛行の切り替え
voxelcraft.villages()                // 知っている町（生産品・原料・需要・段階・在庫。
                                     //   分村は outpost: true と親町の id が付く）
voxelcraft.village()                 // 今いる町、なければ最寄り
voxelcraft.stops()                   // 置いた停留所の一覧（何に付いているか、何本の路線が呼ぶか）
voxelcraft.lines()                   // 路線の一覧と、その区間の状態
voxelcraft.placeStop(x, z)           // 停留所を置く（アイテムも手の届く距離も要らない）
voxelcraft.makeLine(['s1','s2'])     // その停留所を順に呼ぶ路線を作る
voxelcraft.survey(x, z)              // その地面に建てられる産業と、資源の個数・密度
voxelcraft.industries()              // 建てた一次産業の一覧（在庫・出荷済み・産出倍率）
voxelcraft.placeIndustry(x, z)       // 一次産業を建てる
voxelcraft.ledger()                  // L 画面の中身をそのまま（町・産業・区間の一覧）
voxelcraft.earnings()                // これまでに受け取った運賃の総額
voxelcraft.milestones()              // 目標の一覧と、今どこまで進んだか
voxelcraft.quest()                   // チュートリアルの進み具合
voxelcraft.questStep('accept')       // 受注 / 納品 / 道の話 を進める
voxelcraft.gotoQuestTarget()         // 今の目標へ飛ぶ
voxelcraft.buildRoad()               // 目標の 2 か所の間に道を敷く（手作業だと数百ブロック）
voxelcraft.pave(ax, az, bx, bz)      // 任意の 2 点の間に道を敷く（産業への引き込み線など）
voxelcraft.fastForward(120)          // 世界の時計だけを 120 秒進める（待たずに回す）
voxelcraft.resurvey()                // 区間の道を今すぐ調べ直す（普段は 2 秒ごと）
voxelcraft.renderDistance(4)         // 描画距離を変える。小さいほどチャンク待ちが減る
voxelcraft.buildRoad(a, b, 'stone_bricks')  // 舗装し直す（路面の質を試すため）
voxelcraft.sampleRoad()              // 見本の道（＋横を走る途中までの線路）を今ここで敷き、その端に立つ
voxelcraft.roadColumnsNear(x, z)     // その辺りの索引済みの列（掃き敷きが点線になっていないか）
voxelcraft.routes()                  // 輸送路（接続状態・距離・路面・積み荷・荷運び・累計）
voxelcraft.porters()                 // 今出ている荷運びの数
voxelcraft.porterSpots()             // 荷が今どこにあるか（見えていない物も含む）
voxelcraft.guide()                   // 道しるべが描いている線・破線・タイル・光の柱の数
voxelcraft.buildings()               // 今いる村の建物一覧と、どれが集荷所か
voxelcraft.town()                    // 今いる町の人口・建物ごとの用途と在庫・待っている人
voxelcraft.commutes()                // 今その町を歩いている人（見えていない人も含む）
voxelcraft.lookingAt()               // 画面中央の建物と、F で何が起きるか
voxelcraft.setDepot('x0,z0')         // 集荷所を変える（F と同じ扱い）
voxelcraft.roadIndex()               // 索引済みの道の列と改訂番号
voxelcraft.roadFaults(40)            // 敷いたのに数えられていない所と、その理由
voxelcraft.widenRoad()               // 目標の 2 村間の道を幅 3 マスにする（荷車が通るまで）
voxelcraft.buildRailway()            // 目標の 2 村間を線路でつなぐ（曲線・支柱つき。列車が走る）
voxelcraft.sampleTrack()             // 敷設ツールの見本（直線 1 本＋曲線 2 本）を足もとから敷く
voxelcraft.layTrack(a, b)            // {x,y,z,yaw} 2 つで曲線を敷く（狙わずに・材料も要らない）
voxelcraft.layTrackHere(24, 0.6)     // 足もとから yaw 方向へ 24 マス、0.6 ラジアン曲げて敷く
voxelcraft.tracks()                  // 節点・区間・総延長・空いている端の数
voxelcraft.trackEdges()              // 区間ごとの長さ・最小半径・最大勾配・直線か円弧か
voxelcraft.trackAt(id, s)            // その区間の s マス地点の座標（形をそのまま検査する）
voxelcraft.trackTangentAt(id, s)     // 同じ地点の接線（継ぎ目に折れが無いことの確認に使う）
voxelcraft.trackTool()               // ツールを持っているか・始点が置かれているか・下書きの状態
voxelcraft.trackView()               // 描画に渡している中身（区間・支柱・印・下書き）
voxelcraft.splitTrack(id, s)         // その区間を s マス地点で 2 本に割る（分岐・信号の置き場になる）
voxelcraft.switches()                // 分岐器の一覧と、それぞれ何本の枝が出ているか
voxelcraft.putSignal(x, z, true)     // その柱に一番近い線路へ信号を建てる（途中なら割ってから）
voxelcraft.signals()                 // 建っている信号の一覧
voxelcraft.sections()                // 閉塞区間ごとの区間数と、信号に接しているか
voxelcraft.removeTrack(id)           // その区間を 1 本外す（左クリックで撤去するのと同じ）
voxelcraft.clearTracks()             // 敷いた線路を全部消す
voxelcraft.trackDeckAt(x, z)         // その柱の甲板の高さ（無ければ null）— 上を歩ける面そのもの
voxelcraft.creative()                // デバッグ: 全アイテム無限の入切（引数で明示も可）
voxelcraft.giveAll()                 // 入るだけ全アイテムを持ち物へ（棚は C で開く）
voxelcraft.setSpeed(8)               // ゲーム速度（1/2/4/8/16。世界の時計だけ）
voxelcraft.speed()                   // 設定値と、フレームが実際に回せた実効値
voxelcraft.advanceTransport(600)     // 輸送の時計を秒で進める
voxelcraft.discoverNearby()          // 周囲の村をまとめて発見済みにする
voxelcraft.position()                // 今の座標とチャンク
voxelcraft.warp(120, -340)           // その柱の地面の上へ（第 3 引数で高さも指定できる）
```
